## 1. 结论

**现状不能上架。** 主流程在"理想路径"上能跑，但真实使用里有 4 处功能直接失效，且公开材料存在明确的审核风险。

浏览器实测确认的 4 个核心故障：

| # | 现象 | 实测结果 |
|---|---|---|
| 1 | 页面停留约 30 秒后点"还原"，**被藏的元素回不来**（标题回来了，元素还藏着） | 自然空闲 45 秒后切原样：标题已还原、`#site-header` 仍是 `display:none` |
| 2 | 悬浮按钮菜单点「编辑规则」**不会打开编辑面板，反而把页面切回原样**；默认右下角时菜单直接**弹到屏幕外** | 真实鼠标右键→点击菜单项：编辑面板未出现，开关被切到原样；默认位置时菜单底边 616px > 视口 600px |
| 3 | 扩展**重载/更新后，所有已配置站点全部失效**（不再注入、不隐藏、无按钮） | `chrome.runtime.reload()` 后新开页面：无悬浮按钮、元素未隐藏 |
| 4 | 点选**没有 class 的元素**（真实站点里很常见）保存出一条**空规则**；点选某些元素会生成裸标签选择器 `a`/`div`/`li`，**整页同类元素全部消失** | jsdom 探针：无 class 元素候选为 `[]`；`<li class=rec-card>` 候选含 `li` |

审核风险最高的 4 件事：
1. 商店截图 3 是**报错画面**且写着「不支持**伪装**」；截图 4 写着「反而**泄露**」；截图 1/2 用了「微信读书」商标和《三体》书名作者（D1–D3）。
2. 默认标签页标题「新建标签页 / New Tab」+ 空白图标，触及政策条款 *"must not mimic functionality or warnings from a user's operating system or browser"*（D4，见第 2 节决策 1）。
3. README / CHANGELOG / package.json / GLOSSARY 仍以"上班时一瞥之下不像它自己 / disguise"为卖点；政策明确适用于落地页，仓库就是落地页（D6、D24）。
4. 商店名称与简短说明**只能来自 manifest**，现有上架教程让你"在控制台各填一份中英文"是做不到的；不加 `_locales` 英文商店页就是中文简介（D5）。

另外一个工程层 P0：**干净 clone 后 `npm test` 和 `compile` 都失败**（缺 `postinstall: wxt prepare`，Q35）。

## 2. 需要你拍板的决策

### 决策 1：伪装态标签页的默认图标和标题（你提到的"图标不喜欢"）

先说事实：
- **现在的默认图标是个 bug**：代码注释写"透明图标"，但那张 1×1 图片解码后是 RGBA(0,0,255,127)，即**半透明蓝色方块**。标签页上看到的那个淡蓝色小方块就是它（已验证）。
- **Chrome 自己的新标签页在标签栏上不显示任何图标**（Chromium 源码 `favicon::ShouldDisplayFavicon` 对新标签页返回 false，标题直接左对齐）。普通网页没法"去掉"图标位：只要是网页，Chrome 就会留一个 16px 图标位。所以网页能做到的最接近效果是**图标位留空**（真正全透明的图标）。
- 文档里"透明图标会显示通用地球"的说法不对：图片加载成功就显示图片本身，全透明就是空白。只有没有图标或图标加载失败才显示地球/默认图标。

政策风险：商店政策写明产品 *"must not mimic functionality or warnings from a user's operating system or browser"*。把**默认值**设为"新建标签页 + 空白图标"，商店文案还主动这么宣传，审核员容易认定为模仿浏览器界面。**用户自己在设置里填什么标题**是用户的选择，风险小得多。

| 方案 | 做法 | 像新标签页的程度 | 审核风险 | 我的看法 |
|---|---|---|---|---|
| A | 默认图标改为**真正全透明**（图标位留空），默认标题保持「新建标签页 / New Tab」，商店文案照常宣传 | 最像（只差图标位那 16px 空白） | **高**：默认就模仿浏览器，文案还点明 | 不推荐 |
| **B（推荐）** | 默认图标改为**真正全透明**；默认标题改为中性文字（如「阅读」/ "Reading"，或你定的词）；管理页提供一组"快捷标题"（design.md 本来就规划了"快捷推荐一键填入"），其中包含「新建标签页」，由用户自己选 | 用户选了快捷标题后与 A 相同 | 低：默认不模仿，模仿是用户自选；公开材料只写"自定义标签页标题和图标" | 推荐：你要的效果点一下就有，上架面上又安全 |
| C | 保持现状默认值，只在公开材料里不提 "New Tab" | 同 A | 中：行为没变，审核员实测时仍能看到 | 不推荐 |

不论选哪个方案：**绝不使用 Chrome 的 logo 或 Chrome 内置图标的复刻**（商标与"冒充浏览器"双重风险）。

### 决策 2：隐私表单怎么勾

扩展在本机保存了站点地址、URL 路径前缀、取自页面文字的 8 字元素名。官方 User Data FAQ 要求"仅本地处理的数据也要披露"，但纯本地扩展业界普遍不勾数据类型。两种做法见 appendix-store D8。**推荐勾选 "Website content" + "Web history" 并在隐私政策里写明"仅存本机、从不传输"**：最稳，代价是商店页会显示"处理此类数据"。无论哪种，隐私政策都必须如实列全（附录已给全文）。

### 决策 3：仓库里的真实网站截图

`docs/dev/evidence/real-*.png` 含得到的真人照片、墨问用户昵称和私人帖子、微信读书 logo 与书封。建议从仓库删除，并在 AGENTS.md 增加"真实网站截图不入库或先打码"规则。**是否改写 git 历史彻底清除**需要你定：改写历史要 force push，不可逆。不改写的话，旧提交里仍能翻到。

### 决策 4：其它需要你提供或确认的

- 隐私政策需要一个你会查看的**联系邮箱**（商店要求）。
- 仓库 `.npmrc` 写死了 npmmirror 镜像，lockfile 里 322 个包地址全指向镜像，海外贡献者和 GitHub Actions 都会受影响。建议把镜像挪到你个人的 `~/.npmrc`（你本机速度不变），仓库 lockfile 改回官方源。
- 主分支是否改名 `main`：隐私政策链接依赖分支名，建议定下来后不再改（或改用 GitHub Pages 链接）。

## 4. 页面内界面与扩展页面（N 编号，细节见 appendix-ui.md）

**P0**
- **N1 编辑面板打不开**（实测）：菜单项是胶囊根节点的子节点，`pointerdown` 冒泡到拖动逻辑，松手即切换开关。popup 也没有编辑入口。修复：主按钮 + 独立"⋯"按钮，菜单走 Popover；popup 增加「编辑当前网站」入口（不违反"永不做"）。
- **N3 用户可见文案仍有「伪装 / 泄露」且已进入商店截图**：`core/origin.ts` 四条不支持提示、管理页标题说明。

**P1（摘要）**
- 向导状态机缺陷链：序号牌重号（N6）、改一项后其它幽灵标记坍缩为 0×0（N7）、幽灵框盖住重排上来的内容并拦截点击（N8，截图 2 可见）、预览阶段 Esc 失效 + 确认框上按 Esc 反而直接退出（N9）、「只藏这一个」不刷新预览（N10）、「移出本次选择」没移出（N11）、「继续选择」清空所有调整（N12）、「选大/选小」作用在鼠标路过的元素上（N13）、滚动后点选到旧元素（N14）、工具条盖住最常要藏的顶部导航（N15）。
- 悬浮按钮：触屏 `pointercancel` 残留监听导致之后点页面任意处都切换开关（N16）；位置存视口坐标，窗口变小后跑出屏幕（N17）；菜单向下、向右出屏，不能点外面关闭（N18，**实测**）。

- 管理页：任何存储变化整页重载，正在输入的标题被冲掉（N19）；「整体替换」导入无确认（N20）。
- 宿主是普通 `div`：`html>div{display:none!important}`、`div:empty`（宿主无 light 子节点，能匹配）等页面 CSS 能直接干掉整套页内界面；继承属性泄漏进 shadow（N40）。修复：自定义元素宿主名 + 用 USER 样式表通道给宿主上 `!important` 保护 + shadow 内 `all:initial`，或直接用 WXT `createShadowRootUi`。
- 无障碍：胶囊/菜单/对话框都不是语义控件、无焦点管理、提示无 live region（N29–N32）；主按钮白字 on `#3575e0` 只有 4.40:1，胶囊文字在白底页面 2.03:1，`#999` 说明文字 2.85:1（对比度表见附录）。
- 遮罩：深色页面上浅灰贴片 15:1 极其刺眼；点击穿透；不在 shadow 里（N25）。
- 引导：新装扩展默认藏在拼图菜单里，第 2 步"点右上角图标"新用户找不到（附录 §7）。

**旧审查勘误**：Vue 3 不会把 DOM Element 包成代理（无判等 bug）；popup 监听器不算泄漏；导出时立即 revoke、onboarding `window.close()` 在 Chrome 下可用（降为 P2）；工具条 `#aaa` 文字对比度 6.39:1 达标（问题是 11px 太小）。

**视觉方向**（附录 §7 有完整 tokens）："安静的纸面"：中性暖灰 + 克制的蓝 `#2563eb`，浅色/深色两套（`light-dark()`），字号 12/13/15/20，间距 4 的倍数，圆角 8/12。页内浮层统一浅色实底卡片，不再混用深色玻璃；胶囊为实底药丸 + 图标 + 短文字，静止时降低存在感，悬停/聚焦时完全不透明。

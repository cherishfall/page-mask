# PageMask 0.1.0 上架前全面审查（2026-10-27）

审查依据：`chrome-extensions` skill（MV3 规则、上架清单）+ `modern-web-guidance` skill（无障碍、对话框/菜单、暗色模式等现代 Web 规范），对照 `docs/design.md` 与 ADR。
审查范围：`core/`、`entrypoints/`、`ui/`、manifest（WXT 配置与构建产物）、图标与商店素材、README/CHANGELOG/PRIVACY/商店教程。
基线：`npm run compile` 通过，`npm test` 64/64 通过。

结论一句话：**主流程能跑，但有 3 类问题必须在上架前修**——① 后台状态放在内存里，Service Worker 休眠后「切回原样」会失效；② 导入配置可注入任意 CSS（含外链），且导入后站点没有授权、什么都不生效；③ 图标/截图/文案不达商店质量（图标像待办 App、尺寸不全、截图用了「微信读书」商标且看不出价值、README 仍有「伪装」字样）。

严重度：**P0** = 上架前必修（功能失效 / 安全 / 审核风险）；**P1** = 明显影响体验或质量；**P2** = 打磨项。每条末尾 `→ Tn` 指向第 7 节的任务票。

## 1. 引擎与后台（Service Worker）

| # | 级别 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| E1 | P0 | 后台用内存 `Map`（`lastCssByTab` / `draftCssByTab`）记录每个标签页注入过的 CSS，`removeCSS` 依赖它 | MV3 的 Service Worker 空闲约 30 秒就会被浏览器回收，Map 清空。之后点「还原」，后台找不到上次注入的文本，**样式删不掉，页面还原不了**（skill 强制规则 #7）。E2E 一般在 SW 存活期内跑完，所以测不出来 | 把「每个标签页注入了什么」存进 `chrome.storage.session`（浏览器关闭即清空，SW 重启不丢），或改由内容脚本自己保存并在还原时把文本发给后台 → T2 |
| E2 | P0 | 一条规则的多个候选选择器用 `, ` 拼成**一个**选择器 | ① 任意一个候选写法非法（高级后门手改、导入文件），整条规则全部失效；② 隐藏的是所有候选命中元素的**并集**——任一候选比主选择器"宽"（例如去掉 nth 后命中一大片），就会误藏别的东西；网站改版后备选候选突然命中别的元素也一样 | 每个候选单独一个 CSS 块；生成候选时只保留"命中集合与主选择器完全一致"的候选 → T2 |
| E3 | P1 | 内容脚本 `runAt: document_idle`，还要再走一次消息到后台才 `insertCSS` | 每次打开/刷新页面，要藏的元素和**真实标题先闪一下**——对"不想被看到"的场景恰好是最致命的那一瞬 | 动态注册改 `document_start`，脚本一启动就请求注入 CSS、先压标题；DOM 相关的（遮罩、体检、悬浮按钮）等 DOM 就绪再做 → T2 |
| E4 | P1 | 用户在 `chrome://extensions` 里手动收回某站点权限后，站点配置、动态注册都还在 | 弹窗仍显示"清爽中"但什么都不生效，用户无从得知原因 | 监听 `permissions.onRemoved` 做清理/标记；弹窗检测"有配置无授权"时显示「重新授权」按钮 → T3 |
| E5 | P1 | 没有任何启动时对账：`onInstalled`（update）/`onStartup` 不检查"配置 ↔ 授权 ↔ 动态注册"三者一致 | 扩展更新、导入、权限变动后可能出现半残状态 | 新增一个对账函数，在安装/更新/启动时跑一遍（幂等）→ T3 |
| E6 | P2 | `resetSite(...).then(...)` 混用 `.then` | 风格不一致（skill 规则 #5） | 顺手改 async/await → T3 |
| E7 | P2 | 未声明 `minimum_chrome_version`；`insertCSS origin:'USER'`、动态注册 `runAt`/`persistAcrossSessions` 都有版本要求 | 老版本 Chrome 用户安装后静默失败 | 声明最低版本（建议 ≥ 120）→ T10 |

## 2. 内容脚本运行时

| # | 级别 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| C1 | P1 | 扩展更新/重载后，旧内容脚本成"孤儿"：`setInterval` 继续跑、悬浮按钮还在但点了报 "Extension context invalidated"；`__pagemaskLoaded` 标志还可能挡住新脚本初始化（需实测） | 用户更新扩展后，已打开的页面上按钮失灵 | 用 WXT 提供的 `ContentScriptContext`（`ctx.onInvalidated`、`ctx.setInterval`）统一收尾 → T4 |
| C2 | P1 | SPA 路由变化靠每秒轮询 `location.href`，所有已配置标签页常驻 | 轻微耗电；切页最多晚 1 秒生效（这 1 秒里旧规则/新页面内容会闪） | 用 WXT 的 `wxt:locationchange` 事件（成熟封装），轮询仅作兜底 → T4 |
| C3 | P1 | 页面内界面（悬浮按钮/向导/编辑面板/遮罩容器）挂在 Shadow DOM 里，但宿主没有 `all: initial` 重置；样式全部写成内联对象 | 页面的继承样式（字体、行高、颜色、`direction`、`text-align`）会漏进来，个别站点上界面变形；内联样式难维护、三处重复 | 改用 WXT 的 `createShadowRootUi`（自动样式隔离 + 卸载清理，社区成熟方案），样式回到 `<style scoped>` → T4 |
| C4 | P2 | 悬浮按钮每次 storage 变化都"卸载重建" | 无谓开销，拖动/菜单状态会丢 | 改成响应式 props → T4 |
| C5 | P1 | 方案 C 遮罩只在应用时 `querySelectorAll` 一次 | SPA 后加载的元素（瀑布流、延迟加载的推荐栏）**不会被遮住**；A/B 方案靠样式表天然覆盖，C 没有 | 节流的 MutationObserver 补挂遮罩（design.md 已允许遮罩用 MO）→ T5 |
| C6 | P2 | 遮罩用常驻 rAF 循环逐帧 `getBoundingClientRect` | 有遮罩的页面持续占用主线程 | 静止时停帧：滚动/resize/ResizeObserver 触发时才跑若干帧 → T5 |
| C7 | P2 | 体检结果写回 storage 会触发**所有同站标签页**整体重应用（移 CSS、重建遮罩、重建按钮） | 多标签页时轻微闪动 | 体检字段变化不触发重应用（对比变化内容再决定）→ T4 |

## 3. 数据与存储

| # | 级别 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| S1 | P0 | 导入只校验了 `formatVersion/origin/hideRules 是数组`；候选选择器、图标、策略值都不校验 | **安全**：导入别人分享的配置文件，选择器里写 `x{} body{background:url(https://…)}` 即可向该站点注入任意 CSS，包括外链请求（CSS 读取页面输入值的外泄手法是公开技术）；`faviconDataUrl` 填 http 地址会让页面去请求远程图片——与"无网络行为"的隐私声明矛盾 | 新增统一校验：每个候选必须是单个合法选择器（不含 `{ } ; @`，且 `CSS.supports('selector(...)')` 通过）；图标只接受 `data:image/` 且限大小；策略/范围值白名单。导入、高级后门、生成 CSS 三处都过同一道校验 → T1 |
| S2 | P1 | 所有写入都是"拿着自己手里的旧副本整体覆盖"（popup、管理页、编辑面板、内容脚本体检各持一份） | 并发时**丢更新**：例如编辑面板开着时在 popup 切了开关，编辑面板下一次保存会把开关改回去 | 存储层提供 `updateProfile(origin, 改动函数)`：每次写前重新读最新值再改 → T1 |
| S3 | P1 | 导入后的站点没有主机授权、没有动态注册 | 换电脑导入后**什么都不生效**——这是导出/导入功能的主场景 | 管理页对"有配置无授权"的站点显示「授权并启用」（权限请求必须由用户点击触发，可批量一次请求）→ T3 |
| S4 | P1 | 「整体替换」导入只删了配置，没撤销被删站点的注册与授权 | 残留注入与权限 | 替换后跑一次对账（E5）→ T3 |
| S5 | P2 | 图标上传不限大小不压缩，原图 data URL 直接进配置 | 每次写配置都搬运大字符串，并广播给所有标签页 | 用 canvas 缩到 32/64px PNG 再存，限制上传尺寸 → T8 |

## 4. 向导与编辑面板（功能缺陷）

| # | 级别 | 问题 | 建议 |
|---|---|---|---|
| W1 | P0 | 编辑面板「重选元素」**先删除旧规则**再打开向导；用户在向导里取消 = 规则永久丢失 | 新规则保存成功后再删旧规则 → T6 |
| W2 | P1 | 新站点首次进向导后取消：已授权、已注册、已建空配置，页面上留下一个悬浮按钮 | 新站点在首次保存前不落库；取消时撤销授权与注册 → T3 |
| W3 | P1 | 预览中勾选「只藏这一个」后重新生成了候选，但**没刷新预览**，看到的效果与保存的不一致 | 切换后重新 `applyPreview` → T6 |
| W4 | P1 | 高级后门多行文本整体拿去 `querySelectorAll` 校验——换行在 CSS 里等于"后代"关系，校验的根本不是用户写的那几条 | 逐行校验，每行都要过 S1 校验且现场命中 → T6 |
| W5 | P2 | 编辑面板删除规则无确认、无撤销；面板持有过期副本（见 S2） | 删除后给 5 秒「撤销」；改用 `updateProfile` → T6 |
| W6 | P2 | popup 打开向导后用 `sleep(200)` 重试 10 次 | `executeScript` 返回时脚本已执行完毕，可直接发消息；失败时给用户提示而不是静默 → T3 |

## 5. 界面、无障碍与现代 Web 规范

modern-web-guidance 对应指南（实现时请 `npx -y modern-web-guidance@latest retrieve <id>` 拉取）：`switch`、`dialog`、`light-dismiss-a-dialog`、`menu`、`viewport-aware-dropdowns`、`dark-mode`、`accessibility`。

| # | 级别 | 问题 | 建议 |
|---|---|---|---|
| U1 | P1 | 悬浮按钮是 `<div>`，键盘无法聚焦、读屏软件读不出；编辑入口**只有右键**，用户很难发现 | 改成真 `<button>`（带 `aria-pressed` 与可读名称）；菜单入口改为按钮旁的小箭头/长按，右键保留为快捷方式 → T7 |
| U2 | P1 | 悬浮按钮菜单固定向下弹（`top:120%`），而按钮默认就在右下角——**菜单会弹出屏幕外**；也没有点外面关闭 | 用 Popover API（顶层显示，自带点外部关闭/Esc）+ 视口边缘自动翻转（`viewport-aware-dropdowns`）→ T7 |
| U3 | P1 | 向导/管理页的确认框是普通 `div` 遮罩：不抢焦点、Tab 键会跑到页面后面、Esc 不统一 | 用原生 `<dialog>` + `showModal()`；顶层显示还顺带解决页面 `z-index: 2147483647` 抢层的问题 → T7、T8 |
| U4 | P2 | 弹窗的开关是写着"清爽中/原样"的普通按钮，无 `role="switch"`/`aria-checked` | 用 `switch` 指南的原生开关写法 → T8 |
| U5 | P2 | 管理页 `<label>` 未关联输入框；文件上传是裸 `<input type=file>` | 关联 label、美化上传按钮 → T8 |
| U6 | P2 | 扩展页面没有暗色模式 | `color-scheme: light dark` + `light-dark()`（`dark-mode` 指南）→ T8 |
| U7 | P2 | 弹窗加载中/不支持页面时 `reason` 为空字符串，会显示空白提示 | 补兜底文案 → T8 |

### 图标方案（供你选，推荐 A）

- **A 浏览器窗口 + 擦除带（推荐）**：圆角浏览器窗口线框，中间一条内容被"折叠/擦掉"露出干净留白。直接表达"收起页面干扰"，16px 下仍可辨认（窗口轮廓 + 一条横带）。
- **B 半张面具**：呼应 PageMask 名字，记忆点强；但"面具"容易让人联想到"伪装"，与清爽定位略冲突，审核观感不如 A。
- **C 扫帚/魔术橡皮**：语义直白，但同类"清理工具"图标很多，辨识度一般。

配色建议保留现有蓝色（与界面主色 `#3575e0` 一致），去掉绿色对勾。

## 8. 不在本轮范围

- 扩展内全部界面文案的完整英文化（仅 manifest + 默认标题本轮做；完整 UI 国际化视上架后用户构成再定）。

## 9. 待实测确认（审查时未能验证）

- 动态注册的内容脚本在扩展**更新**后是否保留——无论结果如何，T3 的对账都会兜底。
- `__pagemaskLoaded` 标志在扩展重载后是否会阻止新脚本初始化（C1）。
- 带端口的 origin（如 `http://localhost:8080`）生成的匹配模式在授权与注册时是否都被接受。

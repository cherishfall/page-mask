# 整页变灰：一条规则取代按媒体灰度

日期：2026-11-11 · 状态：已采纳 · **修订：[ADR-0013](./0013-media-grayscale-and-curtain-mute.md) 决定 1 与 [ADR-0017](./0017-media-gray-background-image.md)** · 相关：ADR-0002（规则模型与样式表注入）、issue#156

## 背景

按媒体灰度（0.8.0：img/video 灰度 + ≤32px 豁免；0.8.16：背景图打标，ADR-0017）的覆盖边界修了三轮仍不断冒新缺口：0.7.x 灰块被否、背景图站点（多抓鱼）整体失效、推特在错误页建档失败后用户始终没灰成。产品所有者提出：干脆整页变灰——更好做、更不容易出问题。

技术验证（`tmp/probe-wholepage-gray.mjs` / `tmp/probe-gray-a.mjs`，不入库）：`html { filter: grayscale(1) !important }` 一条规则在像素层覆盖一切——背景图、`<canvas>`、**iframe 内容**、内联 SVG、视频全部变灰（旧方案三条边界一次清零）；filter 挂在根元素上不产生把 fixed 元素拖走的容纳块问题（滚动实测 top 恒 0）；文字保持黑字可读；走既有 insertCSS 通道，无新权限。

## 决定

1. **「图片和视频变灰」升级为「整页变灰」**：`mediaGray` 字段名不变（无数据迁移），语义从「按媒体灰」变为「整页灰」。CSS 只有一条规则，不再有任何按元素类型 / 尺寸的例外。
2. **内容脚本缩身**：ui/media-controller.ts 只保留「视频自动播放压制 + 点击放行」（灰度管不住「动」，动比色彩更扎眼）；删掉 MutationObserver、扫描、打标、豁免全套——灰度不再需要认识任何 DOM 元素。
3. **自家浮层一并变灰**：胶囊 / 菜单 / 向导 / 幕布住在页面 DOM 里，祖先 filter 无法被子元素豁免（CSS 物理限制）。功能不受损——状态靠形状（填实/描边）与明度（选中底 vs 透明）区分，在灰度下依旧可辨；危险红失去红色由「整页本就黑白」的产品语义吸收。iOS/macOS 系统灰度对浮层同样全灰，先例支持。
4. **≤32px 小图标豁免退场**：页面自己的按钮图标也灰。豁免曾是媒体路线的机器；整页灰没有例外。
5. **UI 叫法**：「图片和视频变灰」→「整页变灰」（弹窗 / 站点设置页 / 欢迎页 / 胶囊钮读屏名，中英同改）。

## Considered Options

- **保留双模式（整页灰 + 媒体灰并存）**：否决——并存意味着媒体路线的全套机器与全部边界继续维护，与「更不容易出问题」的提案动机相反；整页灰是媒体灰的严格超集。
- **backdrop-filter 全屏遮罩（自家 UI 可保持彩色）**：否决——需要新 DOM 宿主 + z-index 策略，且引入新边界（站点自己 z-index 更高的浮层不变灰）、滚动合成成本；复杂度回到老路。
- **维持媒体路线继续补边界**：否决——三轮返工实证边界按站点而异、永远补不完；用户感知里「某张图没灰」就是功能坏了。

## Consequences

- 一条规则进 buildDisguiseCss 的既有通道：首屏防闪、bfcache、预渲染、向导临时还原、swapCss prev→next 全部自动继承。
- 灰度开启期间页面零 DOM 操作（除视频压制监听），性能特征优于媒体路线。
- 「看起来变灰，不是不加载」的本质不变：请求照发。
- 用户预期迁移：0.8.17 及之前开启过灰度的站点，0.8.18 起变灰范围扩大到整页——方向一致（更灰），CHANGELOG 明示。
- 真机验收清单：多抓鱼（整页灰全覆盖）、X（登录态时间线）、灰-only 建站、两态独立、幕布静音。

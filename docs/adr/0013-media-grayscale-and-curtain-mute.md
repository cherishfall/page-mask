# 图片和视频变灰（灰度降调）与幕布静音

日期：2026-11-07 · 状态：已采纳 · **取代：[ADR-0012](./0012-per-site-media-switches.md)** · 相关：ADR-0002（规则模型与样式表注入）、ADR-0005（按文档注入与首屏遮挡）、ADR-0007（幕布）、ADR-0011（幕布控制器唯一）、issue#131

## 背景

ADR-0012 落地的三个开关（收起图片 / 收起视频 / 静音网页，0.7.0–0.7.1）产品所有者体验后否决了形态，三条证据线：

1. **使用现实**：信息流里的图片大多是要看的内容，灰块把页面变成盲盒——「看 100 张图要点 100 下」；三个平级开关是「设置」的语言，用户要的是「一点就生效」的动作；图片 / 视频拆开在封面图上互相打架（封面是 `img`、播放器是 `video`，两套开关各管一半）。
2. **平台事实（Chromium 源码核实）**：扩展无法干净地代理 Chrome 自带的「静音网站」——`chrome.contentSettings.sound` Chrome 141（2025-09）起才存在且官方 nodoc；`contentSettings` 权限带来安装警告（点名 cookies/JS/摄像头）且存量用户升级后被停用等批准；扩展写入的规则优先级高于用户操作（右键「取消静音网站」失效、设置页删不掉）；写入规则重启即丢（内存存储），「让浏览器帮着记」不成立。另：标签页斜线喇叭只在「静音且最近出过声」时显示，为 Chrome 统一行为。
3. **维护成本**：标签页静音的对账机制（离开恢复、权限收回清理、导航竞态、静音归属）占了 0.7.1 修复精力的一半（#125、#130 及两轮复查）。

产品侧参照（`docs/dev/research-media-hiding.md` 及本轮补充核实）：X Data Saver、Reddit 低流量、微博 App 无图模式都是「一个总开关 + 占位 + 单张点击加载」。降显著性的两派里，灰块（零信息）适合「不想看」，灰度（保结构可读）适合「还要读」——本产品的信息流场景属于后者（产品所有者明示：图片大多是要看的有效信息）。

## 决定

1. **一个按站点开关「图片和视频变灰」**（`mediaGray`，显式 true 落库）取代 `hideImages` / `hideVideos`：图片与视频（含封面帧、暂停首帧）一律 `filter: grayscale(1) !important`——黑白但可读可点、零交互、位置不变；≤32px 小图标与表情豁免沿用 `data-pm-media-keep`。不再使用灰块（`brightness(0)+invert`）。
2. **视频自动播放压制**：`play` 事件（document 捕获阶段）里非用户意图的播放一律按停；「最近一次点击或按键（Enter/空格，10 秒内）落在视频元素内或其三层祖先内」视为用户意图，放行该视频正常播放——放行按文档生命周期记忆，画面保持灰度。**不写任何 `muted`、不碰 `<audio>`**：声音归播放器自己的音量钮与 Chrome 右键静音。
3. **静音并入幕布**：遮住即静音当前标签页（`chrome.tabs.update({muted})`，不需要 `tabs` 权限），恢复即还原；只解除 `mutedInfo.reason === 'extension' && extensionId === 本扩展` 的那份；生命周期与幕布一致——内容脚本 `pagehide` 触发还原，`tabs.onUpdated`（status loading）兜底崩溃路径；未添加网站的一次性幕布同样遮声。`mutePage` 字段与后台整套静音对账（syncMute / releaseMute / shouldMute / 地址变化对账）退场。
4. **入口**：全功能与 mini 胶囊各加一颗「媒体」钮（`aria-pressed`，实心=开、描边=关）；弹窗一行开关；站点设置页一张卡；「⋯」菜单媒体三行退场。媒体开关只在清爽态生效的既有模型不变；原样态下拨「媒体」钮只改设置、页面不动（原样 = 什么都不应用，与 0.7.x 一致）。

## Considered Options

- **真调 Chrome 原生「静音网站」**（contentSettings.sound）：否决——安装警告 + 存量用户停用 + nodoc + 用户右键解除被锁死 + 重启不持久，多重代价换来一个仍要自己记账的机制。
- **保持三开关 / 保持灰块**：否决——形态被产品所有者否决（背景 1）。
- **悬停显示（鼠标移上去恢复、移开再灰）**：否决——摸鱼场景鼠标永远停在某处，走近瞬间亮着的恰好是光标下那张（调研里 Blur. 悬停恢复被否的同款理由）；微博 / X / Reddit 均无悬停恢复。
- **视频只灰度、不压自动播放**：否决——X 信息流自动播放，画面持续在动，动比色彩更扎眼；压制放行靠「点击视频区域」，用户想看的视频不受影响。
- **视频放行后恢复彩色**：否决——看视频期间页面回到「花花绿绿」，与降调目的相反；灰度播放是可接受的折中。
- **媒体层处理声音（写 muted / 管 audio）**：否决——播放器自带音量钮 + Chrome 右键静音已覆盖，扩展平行管理只会制造「忘了哪边静过音」。

## Consequences

- `core/types.ts` / `core/validate.ts`（白名单 + 旧字段迁移）/ `core/apply-key.ts` 三处同步改字段；旧数据 `hideImages || hideVideos → mediaGray`，`mutePage` 直接丢弃（导入 0.7.x 导出文件同样走这条迁移）。
- `ui/media-controller.ts` 大幅缩身：删掉 originalMuted / touchedVideos / restoreVideos 全套声音还原；新增 pointerdown / keydown 意图记录与放行集合。
- 「用户意图放行」的启发式（三层祖先 + 10 秒窗）是真机调参项：微博（点击封面/播放钮）与 X（点击播放器）都要验；不可靠时退到更严的「目标是视频本身或在其内部」。
- 幕布静音让「扩展写的静音」只剩一种来源，#125 / #130 那类「删 A 动 B」的对账问题整体消失；`pagehide` 还原 + `onUpdated` 兜底要覆盖「幕布期间整页跳转」「内容脚本被杀」两条路径。
- 灰度是降调不是伪装：页面从「花花绿绿」降到「像图文资料」，再往上一级的隐蔽手段仍是幕布——这条定位写进 README 与商店材料，不夸大。
- 真机验证清单：明暗底灰度观感、封面灰度、小图标留原样、X 自动播放压制、点击放行、灰度播放流畅度（compositor 滤镜）、幕布静音与还原、斜喇叭显示条件、中英字长。

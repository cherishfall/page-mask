## 一、目标

用户总诉求（原话压缩）：功能排布合理、外观和动效合理、**自解释**、提示语简练准确规范（既专业又易懂）、像个专业人士做的产品、**与胶囊呼应且相互映衬**。

可验收的翻译：

1. 弹窗第一次打开和设置之后打开，**是同一套结构**，不换一套界面。
2. 弹窗从上到下的顺序，与胶囊从左到右的顺序能一一对应。
3. 每块自己说清「这是什么、点下去会怎样」，不靠读文档、不靠猜。
4. 全项目同一件事一个叫法、一个样子；中英两份文案按同样的意思写。
5. 状态变化有 150ms 级短过渡，不 0ms 突变；`prefers-reduced-motion` 下**保留纯色淡变**、只去掉位移/缩放。
6. 悬浮在网页上的东西（胶囊、向导工具条）尽量少挡页面、低调，且给用户能主动让开的路径。

## 二、弹窗最终结构（320px）

`new`（没设置过）与 `ready`（已设置）**共用同一份模板**，只按「对象是否存在」增减三个局部（见 §四）。

```
┌────────────────────────────────────┐
│ PageMask                查看使用说明 │ ← 头部：h1 + 最次要文字链接
│ duozhuayu.com                       │
│ 还没有收起设置 / N 项收起设置        │ ← 一句状态，不念功能名
├────────────────────────────────────┤
│ ① 面具卡                            │ ↔ 胶囊主按钮
│  [面具] 按你的设置显示      [开关]  │   ready：开关
│  没设置过时：一行说明替代开关        │   new：说明（见 §四）
│  ┌──────────────────────────────┐  │
│  │ [ 标题和图标 ] [ 收起内容 ]  │  │ ← 一行并排：同为次操作档（0.8.16 #153 推翻「实心主操作」）
│  └──────────────────────────────┘  │
├────────────────────────────────────┤
│ ② 灰度卡                            │ ↔ 胶囊「媒体」钮
│  [媒体] 图片和视频变灰      [开关]  │
│  一句说明：单独记，不受上面开关影响  │
├────────────────────────────────────┤
│ ③ 遮住卡                            │ ↔ 胶囊「遮住」钮
│  [闭眼] 遮住这一页 / 恢复这一页 ⌘⇧X│
│  一句说明：只挡这一页，刷新就恢复    │
├────────────────────────────────────┤
│ ④ 辅助行（无卡片框）                │ ↔ 胶囊 ⋯ 菜单
│  悬浮按钮  [开关]  / 没设置过时说明  │
├────────────────────────────────────┤
│ [全部网站设置]  [插件设置]          │
│ 删除这个网站的设置（仅 ready/pending）│
└────────────────────────────────────┘
```

### 与胶囊的对应（用户要的「对应关系」）

| 胶囊（左 → 右） | 弹窗（上 → 下） | 为什么这样对 |
|---|---|---|
| 主按钮（面具，切换「按你的设置显示」） | ① 面具卡（开关 + 两个编辑入口） | 主按钮切换的正是这张卡管的那组定制：收起的内容 + 标题图标 |
| 「媒体」钮 | ② 灰度卡 | 同一个开关，两个入口 |
| 「遮住」钮 | ③ 遮住卡 | 同一个页面级动作，弹窗/胶囊/快捷键三处通用 |
| 「⋯」菜单（收起内容 / 标题和图标 ｜ 调整不透明度、放回右下角 ｜ 删除设置） | ④ 辅助行 + 底部删除入口 | 菜单里「管按钮自己」的那一组，与弹窗里管悬浮按钮的设置同类，放最后 |

- 弹窗 ① 内两颗入口的顺序改为 **「标题和图标」→「收起内容」**（用户要的页面顺序）；胶囊 ⋯ 菜单里这两项**同步调换**，否则对应关系断一处（#80 当年就是按弹窗对齐的）。
- ②③ 与 ① 同款卡片框（用户要「样式差不多」）；④ 故意**不做卡片框**，用一条分隔线与四块功能分开——它不是四大功能之一，是「这个入口自己要不要显示」（格式塔共同区域：同框即同组）。

> **对补充调研 §A 的一处有意偏离，记录理由**：`tmp/research-design.md` §A.1/A.4 依 Apple HIG「区分控制与内容」和 GOV.UK「按钮=动作」建议「遮住这一页」**不套**卡片容器、单独做全宽动作条。本方案仍采用同款卡片容器，因为用户这条诉求非常明确（「遮住这一页的样式和上面的差不多」），且与「四大功能一一对应胶囊四段」的核心心智模型绑在一起；**但卡内结构按调研意见做动作化区分**：没有开关、有一颗次操作档按钮 + 键帽 + 一句临时性说明，靠「有没有开关」而不是「有没有框」区分设置与动作。这样既满足同款外观，又不把一次性动作伪装成可记住的设置（`docs/adr/0007`）。

## 三、逐块规格

### 头部
- 左 `PageMask`（h1，20/600），右「查看使用说明」文字链接（12px、`--pm-fg-muted`、下划线、hover 变色）；英文 `View the guide`。
- **为什么仍是文字链接而不是图标**：补充调研 §B.1 建议 header 右上角用 24×24 图标（Apple 本地化长度提醒 + WCAG 2.5.8）。本方案保留文字，是因为把文案从「重看插件介绍」/ "See the intro again" 收短到 6 字 / 14 字符后，320px 与英文态都不再挤压标题；图标含义不自解释，与用户「自解释」总诉求相悖。合规靠两条补齐：`min-height/min-width: 24px` 撑命中区（W3C C42）、`aria-label` 用全称、与 h1 的 24px 圆不相交（WCAG 2.5.8 Spacing 例外）。
- **同一入口跨页面同一叫法、同一相对顺序**（WCAG 2.2 3.2.6 Consistent Help / G220）：本入口当前只在弹窗出现，弹窗内固定头部右侧，不因 `phase` 变化而挪位。
- 欢迎页第 2 步的预览（`PopupBody preview`）隐藏这个链接，避免「介绍页里有个指向介绍页自己的链接」；`tests/onboarding-sync.test.ts` 读的是源码字符串，仍成立。
- 英文按同样的意思重写，不逐字硬译（见 §七文案表）。

### ① 面具卡
- 卡头：**ready** 是「面具图标 + 按你的设置显示 + 开关」；**new** 是同一行位置放「面具图标 + 按你的设置显示」+ 卡内一行短说明（见 §四）。两态卡头高度、图标、文字完全一致，不跳动。
- 卡内两颗按钮**排成一行**：左「标题和图标」、右「收起内容」，**同为次操作档**（浅灰底 + 控件色边框），间距 8px，两颗等高 40px。0.8.15 原方案曾把「收起内容」做成实心 `--pm-accent` 主操作，0.8.16 #153 已由用户推翻（Ant「默认按钮用于一组没有优先级差别的动作」）。
  - 依据 `docs/design-ui.md` §五第 1/2/5 条「一屏一个主操作，永远在最右」「次操作在主操作的左边」「按钮间距 8」——竖排其实一直不符合这条项目共识；左→右也正好是用户要的「标题和图标在收起内容之前」，并与胶囊横向分段呼应。
  - **v3 改并排的直接原因**：A 票实测中文 ready 态 590.3px，距 Chrome 弹窗 600px 上限只剩 9.7px，英文态说明更长且当时没有纵向断言。并排省下约一整行（40px），才有余量把主按钮恢复到「主要提交 40px」、把卡内说明统一到 13px 正文，同时给英文态留安全边际。
  - 蓝底保留，理由是「一屏一个主操作」的项目共识与四档按钮体系（`docs/design-ui.md` §一/§四）；用户问「为什么一直蓝色」，答案是它承担「没设置过时第一步做什么」的指路作用（`research-0.8.15-ui.md` §二.3）。
- 卡内说明统一用 13px 正文档（`--pm-font-size-body`）：三张卡 + 辅助行的说明不许出现 12px / 13px 分叉（AGENTS.md 整屏审查第 5 条）。
- **两态、开关开或关，两颗都可点**。删掉 `:disabled="!switchOn"` 与 `disguiseOffHint`；`PopupBody.vue` 顶部那段「保持可点」的旧注释这次统一为最终结论。
- 开关关着时，卡内不再出现「暂不可用」这类不实说明；如需解释开关管什么，用一句**肯定句**写清它管「收起的内容 + 标题和图标」，且灰度不受它管（自解释，见 §六）。

### ② 灰度卡
- 与 ① 同款 `.popup-card`；一行开关 + 一句说明。
- 说明必须说清「独立于上面的开关」，但要写成肯定句、不用否定式产品黑话（现文案「独立开关，不受『按你的设置显示』影响」要改，见 §六）。
- new 态开关可点，沿用 0.8.5 的首次授权 + 补最小配置流程，行为不变。

### ③ 遮住卡
- 与 ① 同款卡片框；内部是**按钮**（次操作档，不是开关——它是动作不是设置）+ 快捷键键帽 + 一句临时性说明。
- 说明写清「只挡这一页，刷新就恢复」，防止被读成会记住的设置（`docs/design.md` 幕布一节：不写配置、页面级临时状态）。
- 按钮上的闭眼/睁眼图标、快捷键显示、`covered` 状态切换逻辑全部不变，只换容器。

### ④ 辅助行（悬浮按钮）
- **不带卡片框**，与功能四块之间一条 `--pm-border` 分隔线。
- ready：一行开关 + 说明；new：一行说明（见 §四），不显示开关。
- 位置在 ③ 之后、底部页面入口之前（用户要「移到遮住之后」）。

### 底部
- 「全部网站设置」「插件设置」两颗次按钮并排，不变。
- 「删除这个网站的设置」红字文字按钮，仅 ready/pending；**new 不显示**（对象不存在）。
- 删掉原来独占一行的「重看插件介绍」按钮。

## 四、两处「没有照搬第二张图」及理由（需向用户说明）

用户要求「没设置过的网站第一次打开就是第二张图的样式」。**结构、卡片、顺序、文案全部照搬**；只有两处按成熟做法收住，因为照搬会做出「点了没反应」的控件：

| 位置 | 第二张图 | 本方案在 new 态 | 理由 |
|---|---|---|---|
| 面具卡卡头 | 「按你的设置显示」开关 | 同位置放标题 + 一句短说明「设置好之后，用这里的开关在网站原样和你的设置之间切换」；不放假开关 | 开关切换的是已存在的配置。没配置时拨它，要么没反应、要么得凭空建一份配置。Carbon Empty States：「configuration required → 说明原因 + 第一步」；GOV.UK：不要让人猜的禁用控件 |
| 辅助行 / 删除入口 | 悬浮按钮开关 + 删除设置 | 悬浮按钮位置放一句说明「添加设置后，页面上会出现悬浮按钮」；删除入口隐藏 | 它管的东西还不存在；删除没有后果可展示。Carbon：「circumstances under which the data would appear」；GOV.UK：危险按钮只给真实不可撤销的动作 |

**其余 ② 灰度开关、③ 遮住按钮、两颗编辑入口在 new 态全部可点**，与 ready 态一致——它们本来就有首次设置路径（`requestPermission` / `initialMedia` / 一次性幕布注入）。

> 这是本批唯一一处「没完全按用户说的做」。依据写在 `research-0.8.15-ui.md` §二.1；用户醒来若坚持逐控件照搬，再单独开票改，不影响其余实现。

## 五、胶囊开启态与动效规格

### 现状与目标
现状 `ui/toggle/toggle.css` 154–173：主按钮与媒体钮开启态 `background: var(--pm-fg); color: var(--pm-bg)`（整颗墨底反白），0ms 突变。

### 新规格（两颗按钮共用一条规则，一套外观）

| 状态 | 容器底 | 图标色 | 图标形状 | 边界/指示 |
|---|---|---|---|---|
| 关 | `--pm-bg`（中性，透明感） | `--pm-fg-muted` | 描边 | 沿用胶囊分隔线 |
| 开 | **仍是 `--pm-bg`** | `--pm-accent` | 内容填实（与关态不同形） | 该分段 2px `--pm-accent` 描边或底部指示条 |

- 三个独立信号：颜色（5.17:1 / 7.68:1）、形状（填实 vs 描边）、边框（≥3.25:1）。满足 WCAG 1.4.11 的状态 3:1 与 1.4.1 不能只靠颜色；依据见 `research-0.8.15-ui.md` §二.6（含 Figure 6 加粗边框合规路径、M3 Standard/Outlined toggle）。
- **与弹窗同色**：开启态用 `--pm-accent`，和弹窗的开关、主按钮同一个蓝，实现「相互映衬」；现在的墨底反白是无彩色，反而与弹窗蓝色体系脱节。
- `forced-colors` 下改用系统 `Highlight` / `HighlightText`，不靠颜色单独表达。
- 五种状态（默认/悬停/按下/键盘聚焦/不可用）继续沿用 `docs/design-ui.md` §四；开启态的悬停/按下仍有可见变化。

### 动效
- 状态切换给 `background-color / color / border-color / fill` **150ms `cubic-bezier(0.2, 0, 0.38, 0.9)`** 过渡（Carbon productive standard 曲线；150ms = Carbon `duration-moderate-01` / M3 `DurationShort3`）。不写 `linear`，不动 `width/height/top/left`（避免重排）。
- `@media (prefers-reduced-motion: reduce)` 分支**不是置 0ms**：保留 **120ms 纯 `opacity`/`color` 淡变**，只去掉任何 `transform` / 位移 / 缩放。依据 `tmp/research-design.md` §F-5/F-6（Apple 官方：状态变化动画「不应完全去除」，可用渐变/颜色变化）、F-7（crossfade）、WCAG 2.3.3 + C39。上限 <400ms（Doherty Threshold）。
- 过渡只跟随数据状态，不加动画锁；`hover / focus / pressed` 五种状态各自仍有可见变化，过渡不是它们的替代。
- 弹窗卡片出现/隐藏、向导工具条折叠同样遵守：只给短过渡，不做装饰性动画（用户要「低调」）。
- **幕布覆盖/恢复的淡入淡出（调研 §F.4 建议 200ms/150ms）不在本批**：会动到幕布控制器与首屏防闪 E2E，和本批三票无关，登记到后续动效票，不混进来出回归。

### 同步范围（修一类）
`ui/toggle/toggle.css` 两条开启态规则、`ui/FloatingToggle.vue` 的 `data-state` 契约、`ui/popup/PopupBody.vue` 卡头面具/媒体图标 `data-state='on'` 的填实规则、`styles/tokens.css` 顶部对比度表里「bg on fg 是选中态整钮填实的反色对（#137）」注释、`tests/tokens-contrast.test.ts`（若解析该表）、欢迎页第 3 步真实胶囊预览、相关 E2E 断言。

## 六、向导工具条规格

| 项 | 现状 | 目标 |
|---|---|---|
| 宽度 | pick/preview 两步固定 `min(720px, 100vw - 32px)` | 两步**仍同宽**（保住「不变来变去」），收窄到 `min(480px, calc(100vw - 2 * var(--pm-space-4)))`；实现时以「看效果」展开「调整」后不折行/不溢出为验收线，不行就回调到能容下的最小值并留痕 |
| 位置 | 底部居中、可拖 | 保持；**新增「收起」能力** |
| 收起 | 无 | 标题栏右侧一颗轻操作文字按钮「收起」/「展开」（aria-label 写全称）；收起后只剩标题栏一条，页面完全可点；再点还原。收起态不丢草稿、不退出向导 |
| 动效 | 无 | 面板描边与「收起 / 展开」按钮给 **150ms 颜色过渡**；**折叠本身瞬时收起，不做高度补间**；`prefers-reduced-motion` 下保留 120ms 纯色淡变（口径同 §五） |
| 标题和图标单步 | `max-content` 随内容伸缩 | 保持，但核对它不会因上两步收窄而显得是第三种样子 |
| 抓取提示 | 仅 `cursor: grab` | 标题栏加**可见的抓取提示**（浅色抓握点纹 + 微文案「拖动」），照 uBO #1714 的官方补法；不自造新图标语义 |

- 依据：Nielsen #3 用户可控与自由、Fitts（浮层遮挡减少可点区域）、项目 `docs/design-ui.md` §七；720 的原始理由（四列）已不成立。
- 「收起」是新的界面动作，按 AGENTS.md 整屏审查第 2 条：用一个**明确的文字**，不新造图标符号，不与 ✕（移除）、关闭（文字）撞车。
- **不采用补充调研 §D.5 的两条**（记录理由，不是漏看）：
  - 「按阶段分宽」（点选窄 / 看效果 720）：会重新引入用户在 0.8.11 前明确抱怨过的「形状变来变去」，与 #140 的定宽成果直接冲突。本方案改为**两步同宽收窄 + 可收起**，用「让开」而不是「变宽」解决遮挡。
  - 「默认停靠角落」：现有 `left:50%; bottom` 与 `moved` 拖动逻辑、`check-wizard.mjs:348–350` 底部位置断言绑在一起；收窄到 480px 后底部居中已不横穿页面。改角落收益低于回归风险，本批不动。
  - 折叠态不做「悬停半透明自动让开」：WCAG 1.4.13 要求 Dismissible / Hoverable / Persistent，自动让开容易做成「指针一移就消失」，与「自解释」相悖。
- **v4 取舍：折叠不做高度补间（瞬时收起）**，只给面板描边与按钮 150ms 颜色过渡。理由：① 工具条内容是近 400 行模板、多个按 `phase` 并列的分支 + 底部操作栏，为做高度补间要包一层容器，会动到既有直接子选择器、footer 定位与 `check-wizard.mjs` 的几何断言，回归风险远大于装饰收益；② 内容高度随选中项数变化，`max-height` 固定值会做出「前 100ms 看不出变化」的假过渡；③ 这是用户**主动点击**的「让开」动作，按钮文字变成「展开」+ 面板立刻缩短，反馈已经明确，不需要靠动画告知状态（与 §五「状态切换需过渡」不是同一类场景）；④ 瞬时让开反而更快兑现用户「别挡住要点的元素」的诉求（Nielsen #3 用户可控、Doherty <400ms）。`prefers-reduced-motion` 下仍保留 120ms 纯色淡变，只去掉任何位移/缩放。
- **抓取提示按现有条件落地，不新造符号**：`ui/wizard/WizardApp.vue` 的 `.pm-wiz-handle` 里已有 `GripIcon`（六点抓握点纹，`wizard.css` L~86），它就是 uBO #1714 说的「可见抓取提示」，只是颜色偏淡（`--pm-fg-muted`）。C 票只需**提高它的可见性**（例如常态给一层极淡底/把颜色提到 `--pm-fg`、hover 更明显），**不要再加第二个抓握图标、不要加常驻「拖动」文字**——480px 收窄后标题栏空间紧张，且 AGENTS.md 整屏审查第 2 条要求「一个符号一个意思」。`wizard.dragTitle` / `dragAria` 的文案保持不动。

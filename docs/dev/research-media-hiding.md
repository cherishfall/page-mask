# 功能调研：按站点收起图片 / 视频（2026-11-06）

> 对应 spec issue：#116。本文档是两份子代理调研报告的合并存档（产品侧 + 技术侧），
> 供 spec 与后续实现引用。来源链接都在文中；标注「未能联网核实」的条目是二手信息。

## 一句话结论

**可行，且比预想便宜**：不用新权限、不用网络拦截，纯 CSS（`filter: brightness(0) invert()` 灰块）+ 少量 JS（视频 pause/拦 play）就能得到「原生 App 无图模式」的观感，并可并入现有的正式样式表管线。

## 产品侧调研（同类扩展 + 原生先例）

### 同类扩展（6 个 + 1 个方法论参考）

| 扩展 | 用户/评分 | 路线 | 粒度 | 图/视分开 | 形态 | 主要差评 |
|---|---|---|---|---|---|---|
| Text Mode | 6 万 / 3.91 | 网络拦截+DOM 替换 | 全局无白名单 | 打包 | 移除 | 拦截不一致、没 allowlist、破坏站点 |
| Block Image\|Video (Jorvi) | 1 万 / 3.67 | DNR + 内容脚本 | 全局 | 打包 | block/hide 两档 | **视频藏了还在下载**、要 per-site |
| Hide Images/Videos (OmarW) | 3 千 / 4.00 | 纯内容脚本 | **按标签页一次性** | **分开** | 直接隐藏 | **刷新即失效**（头号差评） |
| Blur. | 3 万 / **4.64** | CSS 模糊 | 全局+白名单 | 按类型细调 | 模糊 | 白名单笨重、快捷键不可靠 |
| HoverBlurr (AMO) | 新 | CSS 模糊 | 全局+白名单 | 图片 | **模糊+悬停恢复**、最小尺寸过滤 | — |
| 无图模式 (xzonesoft) | 4 千 / 3.48 | 纯内容脚本 | 全局+白名单 | 打包 | 隐藏 | **关闭后不复原**、部分站失效 |
| nomovdo（开源） | 小众 | 内容脚本禁用视频 | 全局+一键白名单 | 视频 | 禁用不删除（保缩略图） | — |

**抱怨高度集中在三件事**：没有按站点控制、开关不持久、关掉后页面不复原。图/视频分开开关的产品（OmarW、Blur.）评分普遍更高。

### uBlock Origin 的四层机制

网络过滤（`$image`）/ cosmetic（元素隐藏）/ 动态过滤矩阵（`image` 与 `media` 是两个独立类型列）/ hidePlaceholders（默认把被拦元素占位收缩掉——**「页面不能留着洞」是底线共识**）。Per-site 开关排（no-popups / no-large-media / …）里没有 no-images；**所有站点级切换默认临时、挂锁才固化**——「临时为默认、显式才持久」的心智被 uBO 验证不会困惑。

### 原生产品先例（这是「不显眼」的答案）

- **微博 App 无图模式**：配图不加载，**灰色占位块**，想看点哪张加载哪张。网页版微博**没有**官方无图模式。
- **X (Twitter) Data Saver**：图片不自动加载，**低质量模糊预览 + 点 Load 换大图**；视频停自动播放。
- **Reddit Low data mode**：模糊缩略 / tap-to-load 占位。
- **Telegram**：按 网络环境 × 媒体类型 的自动下载矩阵，占位为模糊低清图。

**共同形态**：不加载 + 占位保布局 + 点击才加载。占位块的目的是让页面看起来是「开了省流模式的正常网页」——用户在手机上见过成千上万次（Jakob 惯例），同事瞥一眼不会觉得页面坏了。

### 「模糊+悬停恢复」流派的定位

成熟（Blur. 同类最高分），但定位是**隐私遮挡**（防瞥不防看）。对摸鱼场景的两条反作用：满屏马赛克本身可疑；**悬停恢复 = 同事走近时鼠标恰好停在哪张图上，那张图就是放大镜**。若做可选形态，恢复手势要学 X 的「点击加载」（有意识动作）而非悬停。

### 产品侧综合结论

1. 外观学原生 App「无图模式」：**灰块占位保布局**（不是空洞、不是裂图、不是马赛克）。
2. 骨架学 uBO：按站点状态 + 快捷开关骨架（PageMask 已有：每站两态开关 + 胶囊）。
3. 粒度学全体共识：**图片、视频各一个开关**；按站点（PageMask 的 allowlist 架构天然具备——别做全局，Text Mode 们死在这）。
4. 细节防呆学 HoverBlurr：**最小尺寸豁免**（按钮图标、表情不收，否则页面「坏相」比不收还明显）。
5. **视频必须连声音一起按住**（nomovdo 立项理由）：藏了画面响了声音，比不藏更糟。

## 技术侧调研（可行性）

### CSS 覆盖面逐类核实

| 元素 | 纯 CSS | 坑 |
|---|---|---|
| `img` | ✓ | `display:none` 不阻止 eager 图下载（已核实 Swimburger 实测） |
| `picture` | 无意义 | 透明容器，画面全在内部 `img`（WHATWG 规范） |
| `video` | ✓ | **`display:none` 不会暂停播放，声音照出**（已核实 SO 65042931）——必须配 JS pause |
| `audio` | ✓ | 多数本来不可见；有 controls 的收起后播放继续 |
| `canvas` | ✓ | 无差别杀伤（图表/验证码/画板），建议不默认 |
| 内联 `svg` | ✓ | **图标 vs 插图没有可靠 CSS 区分**；JS 尺寸启发式可做（≤24/32px 豁免） |
| `background-image` | **无纯 CSS 选择器** | `:has()` 不读计算样式（MDN）；`[style*=]` 只覆盖内联；**唯一全覆盖 = JS computedStyle 扫描**（SO 4952337），可参照 `ui/mask-layer.ts` 的节流 MutationObserver 增量扫描 |
| `iframe` 嵌入视频 | ✓（按 src 特征） | 特征串要带分隔锚点（`[src*="//www.youtube.com/embed"]`）防 URL 误伤；广告/评论组件误伤面大 |

### 四种隐藏形态

| 做法 | 观感 | 副作用 |
|---|---|---|
| `display:none`（= 现方案 A） | 布局塌缩、滚动位置漂移 | 懒加载图永不加载；**关掉开关瞬间集中请求几百张** |
| `visibility:hidden`（= 现方案 B） | 原地空洞 | 大片空白像页面坏了；懒加载照发 |
| `opacity:0` | 原地留白 | 需配 pointer-events:none（方案 B 声明已含） |
| **覆盖色块**（= 现方案 C 观感） | 「灰块」而非空洞，像刻意设计 | 纯 CSS 版可用 `filter: brightness(0) invert(N)` 把任何图变**均匀灰块**（保布局、零 JS、合成器友好）——本轮新增结论 |

**用户样式表通道的红利**：我们的 CSS 走 USER origin，**压过站点自己的任何 !important**——站点想用 CSS 把图「救回来」救不回来（ADR-0002 通道设计的直接受益）。

### declarativeNetRequest 路线（评估结论：本期不做）

- session rules 支持 `condition.tabIds` / `initiatorDomains` + `resourceTypes: image, media`；`declarativeNetRequestWithHostAccess` **无安装警告**、只在已授权站点生效——与本项目按站点授权模型同构；配额 5000 条 session 规则充裕；CSS 背景图请求也归 image 类型。
- 但被拦观感 = **裂图图标 + alt 文字**（Chrome 站点禁图的标准样本），必须再叠一层 CSS 修补；video 拦截出播放器报错 UI；站点懒加载骨架屏可能永远转圈。
- **定位**：CSS 路线 = 视觉收起（本项目要的）；DNR = 「连请求都不发」（省流量 + 防 DevTools 暴露面），是另一个产品承诺。CSS 路线的固有暴露面：**Network 面板里图片请求仍在**——需要向用户明示「视觉收起 ≠ 不加载」。

### 与本项目管线的契合（已核对代码）

- `disguiseCssFor` → `buildDisguiseCss` 产出**一份完整样式文本**；`swapCss` 只做整文本 prev→next 换入换出，把文本当不透明字符串——媒体隐藏 CSS 作为确定性常量块 append 进去，**按文档持记录、bfcache/预渲染、storage 联动全部零改动**。
- 视频 pause/拦 play 必须放内容脚本（CSS 管不了）：扫到 `video` 即 pause，并监听 `play` 事件再拉停（站点 JS 会反复调 play）。
- background-image 的 JS 扫描（二期）参照 MaskLayer：节流 MutationObserver + 增量 + 打 `data-pm-*` 标记，标记规则仍走注入管线（`[data-pm-bg] { filter: … }`），依旧不需要遮罩层。

## 综合后的实现路线（比两份报告的原始推荐更进一步）

产品侧推荐「请求拦截为主 + 占位」，技术侧推荐「纯 CSS 并入管线」——综合结论是**第三条路**：`filter: brightness(0) invert(N)` 灰块。

- 观感上达到产品侧要的「无图模式灰块」（均匀灰块、布局不动、链接可点穿）；
- 架构上达到技术侧要的「纯 CSS 文本并入现有管线」（无新权限、无 DNR、无逐元素遮罩、无 MutationObserver——只有视频 pause 的少量 JS）；
- 灰度值可用 invert 比例调（暗色站点的适配留真机调参）；
- 二期增强全部有清晰延长线：background-image JS 扫描（同一 filter 技巧打标记）、单张点击恢复、模糊形态选项、DNR「连请求都不发」档位。

## 风险清单（实现前逐条对答）

1. 视频出声：pause + 拦 play 必做
2. 图标/头像/emoji 误伤：小图豁免 + `img[class*=emoji]` 豁免（X 的 Twemoji 历史，2025-09 起已换回系统字体——保险起见仍豁免）
3. 暗色站点的灰度观感：真机调 invert 比例
4. `filter` 与站点自身滤镜叠加：USER 通道必胜，但站点用 CSS 变量动画滤镜的极端情况留真机验证
5. 灯箱：`img` 选择器天然覆盖；background-image 灯箱漏网（二期）
6. 透明 PNG：brightness(0) 后透明区仍透明（灰形轮廓而非灰块）——观感可接受，真机确认
7. 暴露面：请求照发，明示「视觉收起 ≠ 不加载」

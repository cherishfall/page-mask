## 0.9.3（2026-11-12）：默认键撞 Chrome 保留表，真机反馈收口

用户装机反馈两件事加一问：弹窗「整页变灰」那行没有键帽；设置页第二条命令显示「没有绑定快捷键」却看不到改键的路；问「换了键显示会变吗」。三条其实是一条链。

- **根因查到源码级，不猜**：`Ctrl+Shift+G` / `⌘⇧G` 命中 [Chromium · accelerator_table.cc](https://github.com/chromium/chromium/blob/main/chrome/browser/ui/accelerator_table.cc) 的 `{VKEY_G, SHIFT_DOWN | PLATFORM_ACCELERATOR, IDC_FIND_PREVIOUS}` 与 [accelerators_cocoa.mm](https://github.com/chromium/chromium/blob/main/chrome/browser/ui/cocoa/accelerators_cocoa.mm) 的 `{IDC_FIND_PREVIOUS, COMMAND_DOWN | SHIFT_DOWN, VKEY_G}`。Chrome 安装时静默丢掉建议键：manifest 不变、`commands.getAll()` 返回空串、界面因此没有键帽。ADR-0010 当年记的避让清单 T/N/W/B/O/I/J/C 漏了 G。
- **换键依据**：逐项核对两张保留表，`VKEY_Y` 没有任何 `Ctrl/⌘+Shift+Y` 条目（macOS 只有不带 Shift 的 `⌘Y` 历史记录）；Chrome 官方 commands 文档两处示例也用 `Ctrl+Shift+Y` / `Command+Shift+Y`。与幕布 X 相邻同族。成熟产品里 Dark Reader 用 `Alt+Shift+D/A`、uBlock Origin 干脆不给默认键，但本产品用户明确要「默认快捷键」，故取官方示例键。Y 不再取 Gray 的语义，取舍依据换成「不与浏览器内置冲突 + 与 X 相邻」。
- **本地 reload 不重算建议键**（[SO 21883258](https://stackoverflow.com/a/25654514/5228251) / Chromium `OnExtensionWillBeInstalled`）：已装的本地构建改 manifest 后必须卸载重装，或到 `chrome://extensions/shortcuts` 手动设一个；用户手动设过的绑定在升级时保留。这条写进交付说明与商店材料，不能只说「升级就好」。
- **Chrome 没有「绑定变了」事件**：主流做法是打开时读 `getAll()` + focus / visibilitychange 重读。设置页原本只有 focus，而 Chrome 快捷键页是同一窗口的新标签页，切回来焦点没变 → 会漏。设置页与欢迎页补 visibilitychange；弹窗每次打开都是新文档，天然重读。
- **界面**：改键入口从第一行挪到整张快捷键卡下面（两行共用），未绑定文案补上「系统」；弹窗键帽仍只在真的绑上时出现，不显示假键——Chrome 官方示例 `checkCommandShortcuts()` 也是「检测空绑定并提示」，不是伪造一个键帽。
- **同类位置扫过**：弹窗 / 插件设置 / 欢迎页三处键帽读取、README 与商店材料中英各两处功能描述、§6 审核员备注、GLOSSARY、design.md、core/shortcut 注释与用例、CHANGELOG 与商店版本历史（历史条目保留 G，新增 0.9.3 行）。其余无同类。
- **文案精简轮（同日追加）**：用户说「弹窗文案还是过多」。逐条列出弹窗 ready / new 两态的全部常驻文字后，判定「多」的不是句子长度而是行数：ready 态三条常驻说明里，悬浮按钮那条只是复述标签；new 态三句都在说「还没设置 / 设置后会出现」。按 `docs/design-copy.md` 二、b 与 GOV.UK「hint 不重复控件标签里已有的信息」删掉两行、连 `.aux-hint` 样式一起退场，new 态辅助行整行不渲染。灰度与遮住两条属于三、必须留下，只改措辞：去掉「上面的开关」这种一改布局就失效的位置指代，也去掉「自己记自己」这种把「按网站记」与「独立于主开关」混在一句里的自造说法——用户上一轮刚问「灰度按钮是不记忆的吗」，这句有直接误导。结果 ready 态 3 条 → 2 条、new 态 4 条 → 3 条。

## 0.9.2（2026-11-12）：整页变灰快捷键收口，ADR-0020 修订 ADR-0010

上一会话把功能实现写在工作区未提交（命令声明、三处键帽、后台自动授权），HANDOFF 交下三件缺口：ADR、测试、发版一致性。本轮按 grilling 的设计树把每个分支自查一遍后收口，分三个可验收粒度提交推送，批次结束删 HANDOFF.md。

- **`permissions.request` 的同步回合铁律**：命令按键本身就是用户手势，`onCommand` 必须把事件的 `tab` 参数直接传给处理函数；前面任何 `await`（典型是把 `tabs.query` 写在请求前）都会让请求以 no user gesture 失败。已授权站点 `request` 直接返回 true、不弹窗，未授权站点正好弹 Chrome 的「允许」——「第一次就自动调起授权」靠的就是这一点。别顺手优化。
- **关态写 `undefined` 不写 `false`**：与 `core/media.ts` 的 `mediaFlagPatch`、`sanitizeProfile` 同口径。原来写 `false`，落库会被洗掉、功能等价，但和弹窗开关的落库形状不一致，属于「能跑但要多解释一句」的分叉。
- **Mac 键帽顺序查资料才发现是反的**：查 [Apple HIG · Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards) 明确「多个修饰键一律 Control → Option → Shift → Command」，所以 `Command+Shift+G` 该显示 `⇧⌘G`，不是照抄 Chrome 字符串顺序的 `⌘⇧G`。改唯一出口 `formatShortcut`，幕布与变灰两条命令、弹窗 / 设置页 / 欢迎页三处一起生效——「修一类，不是修一个」。文档里「⌘+Shift+G」是「按哪几个键」的组合说明，与键帽的符号连写是两种语境，Apple 自己也是两种写法并用，不是两套叫法。
- **键位风险如实登记，不谎报**：[Chrome · chrome.commands](https://developer.chrome.com/docs/extensions/reference/api/commands) 只说「某些系统 / Chrome 快捷键（如窗口管理）始终优先、不可覆盖」，没给完整保留组合清单。`Ctrl+Shift+G` / `⇧⌘G` 在 Chrome 查找栏是「查找上一个」、macOS Finder 是「前往文件夹」；会不会被静默不绑定查不到官方结论，交给真机验收，设置页已有「实际绑定 + 未绑定警告」兜底。
- **浏览器级快捷键自动化触发不了**（CDP 只能发页面级按键，ADR-0010 已记）：命令分支用 fake browser 单测覆盖（新增 7 例：翻转、关态字段消失、gray-only 建站、拒绝授权、手势丢失、不支持页面、无网址），既有幕布 6 例保持绿。真机授权弹窗与快捷键面板必须人工。
- **同类位置扫过**：`PopupBody` 只有弹窗与欢迎页两个调用点，两处都传了 `gray-shortcut`；`formatShortcut` 是唯一平台差异出口，组件里没有第二份平台判断；README / CHROMEWEBSTORE 中英各两处功能描述、§6 审核员备注、`docs/design.md` 永不做条目与 ADR 索引、GLOSSARY 三个词条、`public/_locales` 两份说明、设置页动作行与 Chrome 快捷键页说明全部同步。其余无同类。
- **界面验证按用户一贯规矩留给人**：不做截图 / 仿真验证，三处键帽与两条命令的真机路径写成人工确认清单随交付给出，不当作已验。
- **上轮遗留未因本轮改变**：#164（仓库公开 + 隐私政策 URL 点验，只能用户来）、#165（§6 审核员 8 步实走回填）、#178（短名「按设置」等用户拍板）、#37（内容脚本瘦身，P2 延后）、0.9.1 实机体感一轮。

## #162（2026-11-11）：站点身份改成可注册域名

第一阶段（内核，`b32fa39`）换身份与存储/授权/对账；第二阶段补「页面没被授权覆盖」的弹窗提示与全部现行文档。

- **为什么读时懒迁移而不是 `onInstalled.update`**：`onInstalled` 的 update 分支只在升级那一刻跑一次，MV3 后台随时可能被回收，中途被杀就再也没机会补；项目历史里的旧数据也一律是读时 / 净化时懒迁移，没有「一次性重写全库」的先例。读时迁移每次读都先过一遍，幂等、失败下次自动重试，先写后删保证不丢设置。
- **为什么迁移用户沿用旧精确模式**：如果把「有效授权」定义成新的两条通配模式，所有老用户在升级瞬间都会变成「待授权」，内容脚本也要先撤再按新模式注册——升级即失效是最糟的迁移体验。旧模式（如 `https://weibo.com/*`）本身就是有效的 host 权限，继续算这个站点已授权；缺的只是没被它覆盖的页面（典型是子域），由弹窗那句「这个页面还没允许访问」+ 一次点击补上。
- **为什么带端口的站点只能用 http / https 两条模式**：Chrome 的匹配模式里 `*` 方案只能搭默认端口，`*://host:8080/*` 会被判 `Invalid port`，`permissions.request` / `remove` 会整批失败（权限反而收不回来）。协议从 #162 起不参与站点身份，所以显式给 `http://host:port/*` 与 `https://host:port/*` 两条，合起来仍是一个站点。
- **为什么 IP / localhost / 端口特判**：IP 与 `localhost` 没有 eTLD+1；单标签主机名（`intranet`）不是公网域名；带非默认端口的地址可能是本地开发或内网服务，把 `weibo.com:8443` 并进 `weibo.com` 等于把两套环境混成一份配置。E2E 的「一个端口一个网站」夹具也正靠这条成立。
- **PSL 子集取舍**：不内置完整公共后缀列表——体积、更新与维护责任都不适合放进扩展。只收常见多段后缀（`com.cn` / `co.uk` / `com.au` …）与常见私有后缀（`github.io` / `vercel.app` …）；不在表里的后缀按最后一段求 eTLD+1，最坏表现是「同后缀的两个独立站点被当成一个」，配置与授权合并但不丢数据，规则仍按页面 URL 生效。
- **`*://*.weibo.com/*` 是否覆盖裸域**：Chrome 的文档与实现口径长期不完全一致，扩展生态里也各有各的假设。我们不去赌这条边界：`sitePatterns` 对普通域名一律返回「裸域 + 子域」两条，申请、注册、对账、覆盖判断都基于这两条；`isOriginCovered` 按严格口径实现（`*.` 不含裸域）。即使将来 Chrome 放宽，覆盖判断最多更保守一点，真正的生效范围仍由已授权的模式决定，不会多注入。
- **第二阶段为什么还要判页面覆盖**：站点级授权只说明「这个站点有权限」，不说明「当前这个页面在权限模式里」。只允许过 `weibo.com` 的用户打开 `s.weibo.com` 时，按站点能找到配置、算已授权，但内容脚本没注册在这条 URL 上——弹窗显示「就绪」是假话。用 `isOriginCovered(页面 URL, 该站点的有效模式)` 把这种页面并进 pending 档，只换提示句，按钮仍复用既有的 `reauthorize()`（后台申请两条模式、对账、注入），不新增消息类型。
- **验收**：见本票提交正文（`isOriginCovered` 分支单测、迁移 E2E、未覆盖页面的弹窗 E2E）。

## #160（2026-11-11）：收起内容补「恢复网站原来的内容」

- **退路交给确认框，不做批量撤销**：单条删除的 5 秒撤销是「刚删的那一条」的快照，批量清空的退路若也走撤销条，要扩展成整份列表快照，而且向导侧清完即关、没有撤销条的容身之处；两处行为会分叉。所以两处都用同一个二次确认（默认焦点在「取消」，确认按钮红字红边、不填实心红——实心红只留给「删除这个网站的设置」），单条撤销保持原样。代价清空前必须先 `undo.cancel()`：否则先删一条、再恢复内容，之后点撤销会把那条插回刚清空的列表。
- **向导侧先 `setDraft(null)`**：选内容阶段可能正挂着「同类一起」的描边草稿样式；`finish(true)` 只结束向导、不负责撤预览样式（只有 `finish(false)` 会撤），不清就会在页面上留一圈描边。写入失败时保持向导打开，用户还能再点一次。
- **入口判据用总数不用 `initialRules`**：`initialRules` 是「这个页面上用得上的」规则；若拿它判断，规则都作用于别的页面时入口会消失，用户在这个页面上反而没有出口。所以新 prop `savedRuleCount = profile.hideRules.length`（含只作用于别的页面的），管理页同理看 `profile.hideRules.length`。
- **只置空 `hideRules`**：照 #99 的字段纪律，开关、标题图标、灰度、按钮位置与站点授权一概不碰；清到空设置后 #158 的说明与 #135 的会话保留（胶囊当页仍在、刷新后才按 `hasSiteSettings`）都按原有语义自然发生，不另加分支。
- **焦点不能掉回 body**：管理页确认后触发按钮随列表消失，关闭后把焦点交给「收起的内容」卡标题（`tabindex="-1"`）；向导侧清完即关，由页内提示说明结果。
- **验收**：见本票提交正文（patch 字段边界单测、管理页与向导两处入口的取消 / 确认 / 撤销作废、#135 会话保留）。

## #159（2026-11-11）：原样态保存前问「现在打开」

- **#53 的结论收窄到清爽态**：`design.md` 的「保存即完成」与向导里两处「不再弹第二个确认框」写于 #53，当时只考虑清爽态（页面当场变、看得见）。原样态保存后页面没变化，用户会当失败——本次加一次选择，但**不加完成页、不另画对话框**：复用 `pm-wiz-dialog`，两条路都完成保存，区别只在要不要顺手把 `switchState` 写成 `disguised`。

## 0.8.14（2026-11-09，#144）：会话标记的收尾与「显式要求」

- **标记只置位不清除的代价**：删设置 / 一键清空 / 导入整体替换删掉该站 → 页面 `clearPageUi()` 卸胶囊，标记仍是 true；之后该站以「四项全空」形态回来（导入合并写回），挂载门因标记为真而放行 → 胶囊挂到没有任何设置的网站上。修法：`clearPageUi()` 里标记归零（「配置没了 = 这一页的会话结束」）。遮住→恢复、进向导→退出两条路径都不经过 clearPageUi，#143 的语义不受影响。

## 0.8.13（2026-11-09，#143）：会话保留要跨「临时卸载」

- **0.8.7 的会话保留留了个洞**：判据是「胶囊此刻在场（toggleHost 存在）就不拆」，但遮住整页（#50）与进设置向导都会**合法地**卸掉胶囊——从那里返回时配置全空 + 胶囊已不在场 = 判据判「本页没挂出过」→ 不挂。真机路径：灰-only 站点关灰度 → 遮住 → 恢复 → 胶囊消失。
- **修法**：判据改成「**本页生命周期内挂出过**」（页面级标记 `toggleShownThisPage`，挂载成功即置位）。配置全空但本页挂出过 → 保留在场胶囊；从幕布/向导返回时恢复挂载；刷新后仍按四项判据该藏就藏（标记随文档走）；「删除这个网站的设置」照旧立即清场。
- **教训一**：状态机里的「临时卸载」与「永久消失」必须分开记——只看当下在不在场，会把「去别处一会儿」当成「没来过」。
- **教训二**：改这类语义会推翻旧断言（check-wizard 原断言「恢复标题后胶囊也撤掉」编码的是错误行为），改断言前先想清楚哪个语义对：标题回退是清字段、不是删站点，按会话规则应保留入口。
- **教训三**：0.8.11 改欢迎页布局时漏改了 `run-e2e.mjs` 里的引导页断言（全套 E2E 才暴露）——**改界面结构要扫全部引用它的脚本**，不止是主要那个。

## 0.8.8（2026-11-09，#136）：胶囊去把手、整根可拖

- **阈值消歧不能只在胶囊上听 move**：按下后指针一旦移出胶囊，`pointermove` 按命中目标冒泡、不再经过本体——只挂在本体上的 move 监听永远跨不过 8px 阈值，拖动名存实亡（E2E 首跑即抓出）。老把手靠「按下即捕获」绕开了这一点，但按下即捕获会把 click 重定向、吃掉按钮点击（N1 教训）。正解是**按下时挂 window 级 pointermove/up/cancel**、跨过阈值才 `setPointerCapture` 到本体：阈值内保持原生点击语义，跨阈值后 click 落在本体上、按钮不误触。
- **菜单与确认框必须排除在拖动面之外**：popover / `<dialog>` 在 top layer，按下菜单项移动 8px 会吞掉 click、干扰「点外关闭」——`closest('.pm-tg-menu, .pm-tg-del')` 的按下不作为拖动候选。

- **同类不一致顺手修**：触屏 40×40 放大档从 0.8.6 起漏了主按钮（把手在档内、主按钮不在），四颗图标钮一起进档（design-ui.md #109 行同步改，顺带清掉「全功能宽约 164、mini 宽约 74」的 0.5.x 残留数字）。

## 0.7.1（2026-11-06，#125–#130）：0.7.0 发版后的三轮复查收口

- **权限是生效前提，不只是「能不能注入」**（#130）：第三轮独立审查发现 `permissions.onRemoved` 那条收尾是空转的——用户收回站点访问权时配置并不删，`shouldMute()` 只看配置，于是静音不解除、地址一变还可能被双向对账重新静音。把 `permissions.contains` 加进「该不该静音」，单向 `releaseMute()` 与双向 `reconcileMute()` 一起收口。**凡是「按站点生效」的状态，判定条件里都要有站点权限**，光靠内容脚本在不在场不够（躺着 / 失联的标签页没人来收尾）。
- **「删除」不是只有一条路径**：`releaseMute()` 初版复用了双向 `reconcileMute()`，删站点 B 会把站点 A 上用户手动取消的静音按回去（#125）；改成单向解除后，第二轮又发现触发点还有「收回站点权限」和「整体导入替换设置」两条（#128）。修一类问题要顺着「这个状态还可能在哪儿消失」把整类入口走一遍，不能只修报出来的那一个。
- **有状态的 DOM 改写要「一轮一清」到每一个集合**：`touchedVideos`、`originalMuted`、`pending`、`data-pm-media-keep` 四处各自漏过一次，症状分别是「第二次关还原不了」（E2E 抓到）、「渲染尺寸判错」、「后台标签页钉着强引用」、「只关图片时标记残留」。集合增删必须成对检查。
- **「移动」和「移除」不能靠变更记录怎么排来判**（#129）：`appendChild` 一个已在文档里的节点，浏览器常把 removed / added 合进一条 `childList` 记录，jsdom 会拆成两条；按记录判断不是先被 `forget` 抹掉待办、就是把移动当成移除而把视频静音还原一帧。准绳是节点当下 `isConnected`。回归单测只断言最终值看不出「闪一帧」，改为盯住 `muted` 的赋值序列才守住。
- **重判路径要端到端测**：`onLoad` 只把图片放进 `pending`、从不排帧，是 0.7.0 就有的 bug，两轮审查都没报，写「rect=0 → load 后补标记」回归时才抓到（#128）。判定函数测得再细，也代替不了「事件 → 排帧 → 重判」整条链。
- **文档也会失实**：商店材料写「不遍历标签页、不读网址」，实际 `tabs.query({})` 会读 `tab.url`；菜单项数写「seven items」却列了 8 项（拖动悬浮按钮后才有第 8 项）。这两处不影响功能，但会误导审核员，和功能 bug 一起收口（#127）。
- **视觉审查补的是「读得懂」**：组级说明贴着最后一行开关会被读成那一行专属的注脚、菜单未选中项和普通动作项长得一样（#127）。加细分隔与同槽位的淡空框即可，不必新画一套开关外观。
- **验收**：`compile`、单测 693 项、`check:docs` / `check:package`、全套 E2E 9 个脚本合计 842 项断言全绿；#125–#130 逐票提交并立即推送。真机人工路径（授权弹窗、隐私表单、商店八步、截图 4 / 6 重拍）留给产品所有者在提交商店前完成，已写进 `HANDOFF.md` 与商店材料 §0。

## 0.7.0（2026-11-06，#116）：按站点的图片 / 视频 / 声音三个开关

- **产品口径先于代码拍板**：票里正文写「网页静音」、标题写「网站静音」，但术语表里「网站」特指按域名存的那份设置，混用会让人以为这是 Chrome 自带的「静音网站」。开工前定稿为「收起图片 / 收起视频 / 静音网页」，英文 "Hide images" / "Hide videos" / "Mute this page"，并在 `GLOSSARY.md` 登记 Avoid 列。
- **调研推翻了票里的两个默认**：票里原写「小图标本期不做」，但成熟产品的无图模式都豁免按钮图标与表情——全部变灰反而让页面显得坏了；票里原写菜单用 `menuitemcheckbox`，而现有悬浮菜单刻意不是 `role="menu"`（没有方向键导航），孤立用这个角色违反 WCAG 4.1.2。两处都先回报产品所有者，确认「小图标留原样」「用 `role="switch" + aria-checked`」后才写码。
- **灰块不是省流量**：`filter: brightness(0) invert(N) !important` + `background-color` 只改观感，请求照发。这条边界写进了界面说明、README、商店材料与 ADR-0012，不夸大；DNR 拦请求被明确否决（新权限 + 安装警告 + 还原不可靠）。
- **CSS 管不了播放**：`display:none` / `filter` 都不会让 `<video>` 停下来。内容脚本要 `pause()` + `muted = true`，还要在 document 捕获阶段压住 `play`（play 不冒泡但经过 document）。还原只放回改动前的 `muted`，不替网站恢复播放。
- **静音归属**：`tabs.update({muted})` 不需要 `tabs` 权限；解除前核对 `mutedInfo.reason === 'extension' && extensionId === 本扩展`，不抢用户手动静音、Chrome 自带「静音网站」或其他扩展。`tabs.onUpdated` 初版写成「地址变化或加载完成」都触发，会在未添加网站的页面也唤醒后台，收窄成只认 `changeInfo.url`。
- **真机抓到一个单测看不见的回归**：`restoreVideos()` 清了「改过的视频」集合却没删「原静音值」WeakMap，于是「开 → 关 → 再开 → 再关」第二次打开时以为已经记过原值，第二次关就再也还原不了。修法是一轮一清、连原值记录一起删，并补两条循环回归单测。**有状态的 DOM 改写必须按「一轮一清」设计**，这是纯函数式的单测最容易漏的一类。
- **三处界面不许各写一份清单**：`MEDIA_FLAG_KEYS` 是唯一的键 / 顺序来源，`mediaFlagPatch()` 是唯一的写入口径；`tests/media-ui.test.ts` 用源码断言守住三处都用 `v-for`、`t.media[key]`、`role="switch"`。菜单勾选项沿用 `.pm-tg-item`，只多一列固定占位的 12px SVG 勾选标记，点一下不关菜单，可以连着拨几个。
- **验收**：`compile`、单测 679 项、`check:docs` / `check:package`、全套 E2E 9 个脚本合计 841 项全绿；新增 `tests/e2e/check-media.mjs` 24 项专测三处互通与还原。架构决策见 [ADR-0012](../adr/0012-per-site-media-switches.md)，方案与验收留档见 [design-116.md](./design-116.md)。

## #107 幕布唯一控制器：两条实测出的坑（2026-11-06）

实现 ADR-0011 时，方案里没写、靠真实浏览器跑出来的两个坑：

- **「登记者应答」是硬约束，不是优化**。第一版让一次性脚本的监听「每条消息现读登记处、委托给当前控制器」，意图是接管后仍能应答。实测：内容脚本接管登记处后，两个监听器都活着、都动手——同一条 `curtainToggle` 各跑一遍（内容脚本遮上，一次性脚本又切回去），回复还是第二个监听器的「遮上了」。`tabs.sendMessage` 只取第一个**回复**，不阻止其他监听器**执行动作**；唯一安全的规则是谁登记谁应答，另一方静默退位（不占回复通道）。
- **「回复动作后的状态」要求 toggle 把异步交出去**。一次性脚本的 `cover` 要先读存储（异步）；`toggle` 里 `void cover()` 会让回复在遮完之前就发出（`covered:false`），后台以为没遮上。修法：`toggle` 返回 cover 的 promise，监听器 `await` 后再回复。内容脚本的 toggle 是同步的，不受影响。

另：内容脚本在**没有站点配置**时不占幕布消息的回复通道（遮不了页就别承认自己是接收方），否则站点刚删除后注入的一次性脚本会与它报告矛盾状态。同文档「先一次性脚本、后内容脚本」的让位接管会**保留遮住状态**（撤旧层、登记自己、接着遮）——比交接文档定的「只要求一层」多走了一步，理由：用户遮着页面时启用站点，幕布不该消失；E2E `check-curtain-state.mjs` 已覆盖此场景（44 项断言，全绿）。

## #104 图标：一副歪着放在纸上的面具（2026-11-05）

这轮改了十版，值得记的不是结果，是**每一版为什么会死**：

- **“白页 + 横带”永远读成字母 B**（两块白色 + 一条横线），换成角上盖、斜切、缺口都只是在 B / 折角 / 书签之间换。主体是“页面”时，横切构图的宿命。
- **眼罩一旦开眼洞就像“被看着”**；一旦封死就退回蝴蝶结 / 色带。A2 之所以“酷”，恰恰是眼洞给的——这是题材的硬约束，不是调色能救的。
- **倾斜是折中**：把眼罩歪 10°、偏向左上、一角探出纸边，它从“一张正对着你的脸”变成“摘下来放在纸上的物件”，眼洞保留但“被盯”的感觉弱了。
- **白页必须有内容行**：只有纸和眼罩时，眼罩会读成无限符号；加上下方两行灰线，白纸才成立为“一页纸”，眼罩才成立为“面具”。16px 也要留一行，否则退回色带。

- 顺手让 `scripts/gen-icons.mjs` 支持 `CHROME_ARGS`（沙箱 / CI 里要 `--no-sandbox`），此前只有 E2E 的 launcher 认这个变量。

## #102 胶囊不透明度三档（2026-11-05）

- **为什么不是滑块**：滑块会被调到一个谁也复现不了的中间值，想回默认还得靠感觉；三档足够表达「太扎眼」。数值 100% / 85% / 70%，按 tokens 浅色值实算最差文字对比度 15.8 / 9.8 / 5.9，三档都 ≥4.5。
- **边框跌破 3:1 是已知例外**：整颗元素降透明度时，边框相对页面底色的对比必然下降；不降文字、只降底色又会在深色页上变成「深字压深底」。权衡后选择整体降、文字优先保底，并把例外登记在 `styles/tokens.css`。悬停 / 键盘聚焦 / 拖动立刻回到 100%，「淡」只在闲置时存在。
- **强制颜色模式回到 100%**：高对比度用户不该再被压一层透明度。
- **预览用真实组件**：设置页里注入同一份 `toggle.css`，渲染 `FloatingToggle` 的 `preview` 模式（`position: static`、不可拖），外面套 `inert` + `aria-hidden`。预览与真机不会走样——这也是欢迎页那张票要复用的机制。
- 只作用于胶囊；幕布上的「恢复」按钮固定 85%，是遮住后唯一的回家路，不跟随这个设置。

## #101 幕布快捷键：推翻「永不做快捷键」，只开一个口子（2026-11-05）

`design.md` 的「永不做」第一行被推翻了，所以先补 ADR-0010 再写代码。执行时值得记的几点：

- **Chrome 的硬规则**：必须带 Ctrl / Alt（Mac 上是 Command），做不到单键；一个扩展最多 4 个预设键；组合被占时**静默不绑定**，所以设置页必须显示「当前实际绑定」而不是写死默认值；改键只能去 `chrome://extensions/shortcuts`，没有 API。
- **快捷键会授予 activeTab**（Chrome 文档明确列出「commands 快捷键」是用户手势之一）：于是没添加过的网站也能遮，一次注入 `curtain-oneshot.js` 即可。这条让快捷键比「打开弹窗再点遮住」在陌生网站上更可用。
- **命令处理必须有返回 Promise 的监听器**：`commands.onCommand` 的回调同步返回后 Chrome 不管，但单测要等异步分支跑完；让监听器 `return toggleCurtainByShortcut()`，生产无副作用、测试可 await。
- **失败反馈不用通知、不加权限**：`chrome://` 等不能注入的页面，用按标签页的 `!` 角标 + `action.setTitle` 说明原因，3 秒后自己清掉。3 秒定时器在 SW 空闲回收（30 秒量级）之内，不会被截断。
- **测试边界**：CDP 只能发页面级按键，浏览器级快捷键在自动化里触发不了。命令的三条分支（撤 / 遮 / 注入）与不支持页面走 fake browser 单测；真机手测写进验收，交付时不谎报「已自动化验证」。
- 避免与既有断言打架：弹窗按钮里多了一个 `<kbd>`，`textContent` 会带上键位，E2E 改为读 `.popup-cover-label`——按钮的可见文字与快捷键提示从此各自有稳定的锚点。

## #100 同类组统一描边：删掉 1.1 / 1.2 子号牌（2026-11-05）

0.5.5 的「小组挂子号牌、大组画描边」被用户当场识别成 bug（「有的有编号、有的没有」）。复盘时确认它还是个**假承诺**：子号牌长得像清单里的一项，但点它只是跳到同一条规则的行，不能单独操作。

## #98 标题与图标：只改「保存过」的网站（2026-11-05）

0.5.5 装机后用户报「只设了收起规则，标签页标题却被改成『阅读』」。查下来不是渲染 bug，是**模型缺一个概念**：

- 旧模型里「没设过标题」和「设了但留空」都存成 `null`，而取值链总要兜底到「插件默认 / 语言默认」。这条兜底在 0.5.0 之前成立（标题是向导第一步，每个网站都必然经过）；#81 把两条流程拆开后，「只收起内容」的网站成了新状态，兜底就把没设置过的东西改掉了。**流程拆分改变了「空值」的含义，却没改数据模型**——这是整批反馈里最值得记的一条。
- 修法：`SiteProfile.titleIconSet` 把「保存过」变成显式事实；清爽态只在为真时 `guard.apply`，为假时显式 `guard.restore`（之前可能压过）。旧数据按 `!!(disguisedTitle || faviconDataUrl)` 推导——只有那条流程会写这两个字段，所以推断对 0.5.x 存量是准确的。
- 写入点有三处，缺一处就会「保存了却不生效」：向导 `titleOnlyPatch`、管理页标题自动保存、管理页图标上传。用 `grep titleOnlyPatch / disguisedTitle` 把所有写入路径列出来逐个补，比事后按症状修便宜。
- **连带语义变化**：全局「默认标题 / 默认图标」不再自动套到所有网站，只剩两处用途——打开表单时的预填值、遮住整页时的标题与图标。设置页的两段说明同步改写，否则界面在骗人。
- **应用键**：`core/apply-key.ts` 要带上 `titleIconSet`，否则「刚点完保存」不会触发整页重应用（标题要等下一次存储变化才生效）。
- E2E 的两处写法随之调整：`run-e2e` 的种子配置显式 `titleIconSet: true`（它要验证标题补刀与 SPA 翻页重压）；「新站点只保存收起内容」的断言从「标题变成默认」改成「标题保持原样」，并顺带验证「标记翻转 → 标题立刻压上去」。
- **#99 补了出口**：保存过之后要能回到「没设置过」，否则误点一次保存就只能删整个网站。`titleIconResetPatch()` 只动 `titleIconSet / disguisedTitle / faviconDataUrl` 三个字段，向导表单与站点设置页共用；向导侧走 `finish(true, notice)`，收回预览、关面板、给一句提示。

## #81 拆开向导：两条独立流程、无首次模式（2026-11-04）

「收起内容」与「标题和图标」本是两件事（填两个字段 vs 在页面上点选），却共用一个三步壳，「只改标题，完成」是小表单被套进长流程后的逃生门。本次拆开，值得留痕的结构取舍：

- **点选阶段旧项全互动是本次最大的语义变更**：已收起的项不再用「之前收起了」虚线角标标记，而是直接进选择集——与新选的统一编号、进同一份清单。点它 = 取消（草稿一并去掉，等同清单 ✕）；再点 = 按默认值当新的一项加回。原 `onPickBefore` 的「原地替换」手势退场——一个手势只许一个意思。失效行的「重新选」保留，但实现从回调改到 `onSelectionChange` 里检测「新加进来的元素」，重选后的元素留在选择集（草稿已带着它，不会被当成新项重复建）。
- **「选大一点」对旧项需要同步草稿**：`replaceInSelection` 原位换元素只动选择集，旧项草稿的 el / 候选不会自己跟。`adjust()` 里在调整前抓快照：正常替换走 `replaceDraftElement`；「选大成已选中的另一项」等价取消，草稿交给 `onSelectionChange` 的 removed 分支删——两条路径不重叠，靠 `selBefore.includes(next)` 区分。
- **保存路径合流**：原来 `newSite` 纯追加、编辑模式走 `mergeSavedRules`；无首次模式后只剩一条路——`mergeSavedRules` + 空 `editIds`（空数组与 null 在删除语义上等价，纯追加自然成立）。新站点「收起内容」保存只写规则 + 开清爽，**不写标题**（标题属「标题和图标」流程，两流程各管各的字段）。
- **`isDirty` 靠基线快照**：旧项打开时就在选择集里，`selEls.length > 0` 不再是 dirty 证据。打开时记 `baselineDrafts` 签名，无改动时退出不弹确认框（check-toggle 的既有断言得以保留）；「还没进过看效果的新选」用「选择集里存在草稿之外的元素」补判。
- **弹窗权限请求的入口变宽**：新站点现在两颗按钮都要先请权限（`requestPermission: !profile`），「标题和图标」在新站点上也走 `enableSite` + `open: 'editTitle'`（写配置必须先注入内容脚本）。

## 0.5.0 收尾批次（#75–#78，2026-11-04）

用户睡前的六条反馈，一晚三票全落地（行内整理 / 三口归一 / 胶囊 mini）。值得留痕的：

## 0.5.0 · #74 补漏：同一类问题只修了「最先看到的那一处」（2026-11-04）

## 0.2.0 · #25 悬浮按钮与页内无障碍

- **胶囊拆成三段**：拖动把手（专用 handle，`setPointerCapture`，方向键可移动）/ 主按钮（`aria-pressed` + 可见文字「清爽」「原样」+ 状态点）/ 「⋯」菜单按钮。原来整根胶囊是一个 `div`，`pointerdown.prevent` 同时承担拖动与点击，菜单项挂在它的子节点上：点菜单项时 `pointerdown` 先冒泡到根节点把菜单关掉，`pointerup` 又发出 `toggle` —— 这既是 N1 的成因，也是键盘完全用不了的原因。现在菜单项与主按钮是兄弟节点，不再经过拖动逻辑。
- **菜单用 `popover="auto"`**，因此「点外面关闭」「Esc 关闭」是浏览器行为，不用自己挂 document 监听；进 top layer 后也不可能被页面浮层压住。
- **位置自己算，没用 position-area**：项目 `minimum_chrome_version` 是 116，`position-area` / `position-try-fallbacks` / `focusgroup` / `commandfor` 都晚于它。按 `viewport-aware-dropdowns` 的无 polyfill 退路用 `getBoundingClientRect()` 算「上方优先 + 右对齐 + 越界贴边 + 下方翻转」，并用手算 clamp 替代 `position-try`。
- **对比度靠「本体 + 外圈」两条腿**：单一不透明底色不可能对白底、深色、中灰三种页面都 ≥3:1（白底够、中灰 2.64、深底靠本体 18.9）。所以胶囊本体用 tokens 的不透明底（深底过 3:1），再加一圈 `rgb(0 0 0 / 0.5)` 的半透明黑外圈（浅底 3.95、中灰 3.07）。`check-toggle.mjs` 会把外圈按页面底色合成后实算比值，改色值时会报警。
- **位置存储仍是 `{x, y}` 像素**（没有改成「边 + 比例」的数据模型）：松手时把 x 吸附到最近的一条边、y 夹进视口，挂载与窗口变化时再夹紧一次。效果与「贴边 + 比例」相近，但不改动存储 schema、不需要迁移。
- **右键菜单彻底去掉**（「永不做」清单本来就不允许）：`check-toggle.mjs` 有一条「右键胶囊不会打开菜单」守着，防止再把入口加回来。

## 2026-10-26 03:00 · 向导全流程 E2E 通过（真鼠标拾取→预览→保存）

两个通宵踩坑，值得记录：

- **shadow 事件重定向**：shadow DOM 内元素的事件传到 window 级监听器时，target 会被重定向成 shadow host。自家 UI 判定必须同时认 host 本身、host 的后代、shadow 内部节点三者。症状：JS 点击工具条按钮被当成页面点选（还把 host 选中了），且捕获阶段的 stopPropagation 吞掉了按钮本该收到的点击。
- **Vue 响应式代理 × chrome.storage**：响应式代理数组经 chrome.storage 序列化会变成 `{"0":..,"1":..}` 数字键对象，后续 `.map` 全崩。修法在存储层入口（putProfile）统一 JSON 规范化，所有写入方一并治愈。
- **insertCSS 通道**：默认 origin 是 AUTHOR，须显式 `origin:'USER'` 才是设计要求的用户样式表通道；removeCSS 参数必须与插入完全一致（探针脚本验证过 CfT 157 行为符合文档）。

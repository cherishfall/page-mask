# 界面基础规范：色彩、文字、按钮、排布

这份文档管的是「所有界面长得一样、搭在一起不打架」这件事。颜色值、字号这些具体数字在 `styles/tokens.css`，本文说清楚**为什么是这些数字、什么场合用哪一个**。

凡是要新增界面、改按钮、改文案层级，先看这里；这里没写的，按「参考对象」一节的来源去查，不自己发明。

## 一、参考对象与取用

只列真正被用到的规则，不凑数。

| 来源 | 取用的规则 | 用在哪 |
|---|---|---|
| [GOV.UK Design System · Button](https://design-system.service.gov.uk/components/button/) | 一页只用一个主按钮；次按钮用于次要行动；警告色只给「严重且不可撤销」的破坏性动作，并且要再走一次确认；尽量不用禁用态；按钮文字写成「动词 + 对象」；「保存，稍后再来」这类提前结束的路径要单独给按钮 | 按钮层级、文案、禁用态 |
| [GOV.UK Design System · Links](https://design-system.service.gov.uk/styles/links/) | 链接默认蓝色带下划线（「Links are blue and underlined by default」）；只有「上下文已经说明这是链接」的场合（页头 / 侧边导航）才可以去掉下划线 | 文字入口的下划线立场（§四 文字入口） |
| [Carbon · Button](https://v10.carbondesignsystem.com/components/button/usage/) | 主按钮每屏一个；次按钮只与主按钮成对出现，承担这一对里的「反向」动作（取消、返回）；三级按钮最弱；危险色只给破坏性动作 | 向导底栏的主/次/反向关系 |
| [Carbon · Link](https://carbondesignsystem.com/components/link/usage/) | 链接只管导航（「Do not use links for actions that will change data … or trigger an action」）；内嵌链接必须带下划线 | 文字入口的链接 / 按钮分工（§四 文字入口） |
| [Carbon · Type sets](https://carbondesignsystem.com/elements/typography/type-sets/) | 产品界面的 productive 字阶：正文 14、标签与辅助 12、标题 600 字重；标题与正文靠字重区分，不靠字号堆叠 | 字号阶梯与字重 |
| [Ant Design · Button](https://ant.design/components/button) | 一个区块最多一个主按钮；默认按钮用于「一组没有优先级差别的动作」；文字按钮用于最次要的动作；危险色只给删除/授权这类有风险的动作；控件高度 32（默认）/ 40（大）/ 24（小） | 按钮档位、尺寸、行内小动作 |
| 项目既有 `styles/tokens.css` | 语义色 + `light-dark()` + 强制颜色模式；对比度门槛由 `tests/tokens-contrast.test.ts` 守门 | 颜色落地方式 |

六份来源在关键结论上完全一致，这也是判断「某个说法是不是主流」的依据：**主按钮一屏一个、次按钮成对出现、危险色只给不可撤销的破坏动作、文字按钮只给最次要的动作、链接负责导航且默认带下划线**。

## 二、色彩

1. **只有一套强调色（蓝），不按功能上色**。保存、编辑、退出不给不同颜色。颜色只表达两件事：**轻重**（主/次/弱）和**风险**（危险）。「这是干什么的」由按钮上的字说。
   - 依据：GOV.UK、Carbon、Ant Design 都只有 primary / secondary(或 default) / tertiary(text) + danger 这几种，没有「保存色」「编辑色」。
   - 反例的代价：颜色一多，用户看不出哪个是主要的；红绿色弱用户分不出区别；同一动作在不同界面换颜色会让人以为是两回事。
2. **中性色承担层次**：页面底 `--pm-bg`、块底 `--pm-bg-subtle`、控件边界 `--pm-border-control`（≥3:1）、卡片分隔 `--pm-border`（装饰性，不承担控件提示）。
3. **控件必须能被认出来**：输入框、按钮、开关的外框一律用 `--pm-border-control`；纯装饰的线才用 `--pm-border`。
4. 颜色不能是唯一的信息载体：失效、警告、危险都要同时有文字。
5. **「这里有问题」只有一种样子**（#72）：圆点在前、文字在后，同一个 `styles/marks.css`；只有颜色区分「要你处理」（warning，事情还没坏）与「已经坏了」（danger）。不许再出现描边徽标、圆点写进文字里这类第二种写法。

### 浮层边界与投影（#118）

压在网页上的浮层（向导工具条、确认框、菜单、页内提示、胶囊、幕布恢复钮）与网页之间必须**看得见一条边**：

- **真实 1px 描边**：`--pm-border-overlay`（浅 `rgb(0 0 0/.22)` ≈1.69:1，深 `rgb(255 255 255/.20)` ≈1.92:1）。用 `border` 而不是 `box-shadow` 画边——`forced-colors` 下阴影会被浏览器丢弃，只有 border 留得住，此时描边取 `CanvasText`。
- **三层阴影**：`--pm-shadow-overlay` = 近 `0 1px 2px`（贴身处）＋ 中 `0 6px 16px`（主体）＋ 远 `0 16px 32px`（环境）。原来那圈 6% 黑的环在白底上只有 1.14:1、深色 1.28:1，等于没有边界，已删除。
- **不把面改灰**：面板内部已经有浅灰卡片（已选项、调整区），面改灰会跟卡片打架、要连整套层次一起重排。四家做法里，Ant Design 就是纯白面 + 三层阴影、不描边；Fluent 是白面 + 1px stroke（`#D1D1D1`，1.53:1）；M3 与 Carbon 靠色阶分层。
- **门槛**：浮层外框是装饰性边界（不承载「这是控件」与状态），按 WCAG 1.4.11 不设 3:1；面板里的按钮、输入框、滑杆仍由 `--pm-border-control`（3.25:1）承担。
- **不降级已有的边**：菜单、页内提示、删除确认框、胶囊、幕布恢复钮本来就用 `--pm-border-control`，不动——胶囊那圈边是「这是个控件」的识别依据，不能为了统一降到 1.69:1。

## 三、文字

四号字、三种字重、三种颜色，别的不许出现。

| 用途 | 字号 | 字重 | 颜色 | 说明 |
|---|---|---|---|---|
| 页面标题 | 20 | 600 | `--pm-fg` | 每个页面/每个浮层最多一个 |
| 区块标题 | 15 | 600 | `--pm-fg` | 卡片标题、分组标题 |
| 按钮、列表主文字 | 13 | 500 | `--pm-fg` | 按钮标签用 500，因为压在 13px；Ant 与 Carbon 在 14px 正文下用 400 |
| 正文 | 13 | 400 | `--pm-fg` | 说明、表单值 |
| 辅助说明、次要文字、计数 | 12 | 400 | `--pm-fg-muted` | 最小字号，不再往下压 |

- **标题与正文靠字重区分**（Carbon 的做法），不靠无限加字号。
- 行高统一 1.5（大标题 1.3）。
- 数字用等宽数字（`font-variant-numeric: tabular-nums`），避免跳动。
- 正文 13px 是**有意低于 Carbon 的 14px**：本扩展的界面是压在其他网页上的浮层，字大了会喧宾夺主；代价是可读性略低于 14px，因此不再往下压，且辅助说明只用 12px。

## 四、按钮

### 四档

| 档位 | 外观 | 用在哪 | 一屏几个 |
|---|---|---|---|
| 主操作 | 实心强调色，白字 | 这一屏最想让人做的那件事 | 最多一个 |
| 次操作 | 浅灰底 + 控件色边框 + 深色字 | 与主操作并列的另一条路；后退、保存、退出设置 | 可以多个 |
| 轻操作 | 无底无边，文字色略淡 | 只给内容里的小动作：取消选择、去掉某一项 | 不限 |
| 危险 | 红字红边；只有最终确认那一步才用实心红 | 删除、清空 | 同一屏最多一个 |

- **操作栏里出现的都得是看得出来的按钮**（有底或有边）；只有内容里的小动作才用不带框的文字。
- **没有值得主推的动作时，可以一屏零个主按钮**（0.8.16 #153）：弹窗的两颗编辑入口是「一组没有优先级差别的动作」（Ant 的默认按钮语义），同为次操作档；待授权态的「允许访问」是该屏唯一动作，才是实心。
- **图标开关（icon toggle）的选中态 = 填实图标 + 淡灰选中底，不用强调色**（0.8.16 #152）：依据 M3 icon button（toggleable：选中 = filled icon + secondaryContainer 淡色容器，不用 primary）、Carbon 工具栏图标选中态（layer-selected 淡灰底）、iOS 控制中心（激活 = 色调底 + 填实图标）。胶囊两颗开启态按钮是落地实例：图标 `--pm-fg-muted → --pm-fg`（墨色浓淡）、图标填实 vs 描边（形状）、`--pm-bg-selected` 选中底（辅助信号），颜色不单独承载状态（WCAG 1.4.1）。0.8.15 的「强调色图标 + 底部 2px 指示条」按用户反馈退场——指示条与胶囊边框读成两道重复的线。
- 危险色不许用来「吸引注意力」：GOV.UK 明确要求不能只靠红色表达严重性，必须有文字写清后果。
- **危险色的两档用法**（#178-3，#160 有意）：红描边（危险档）给「发起点」——列表 ⋯ 菜单里的「删除这个网站的设置」、「恢复网站原来的内容」这类还在斟酌的入口与确认框的取消侧；实心红（`primary.danger`）只给最终确认那一步——确认框里的「删除设置」「确认替换」。删站点连权限一起收回、后果比单条收起项更重，所以「发起」与「最终确认」分两档，让最后一步更扎眼。GOV.UK 的 warning button 同构：「Warning buttons are designed to make users think carefully before they use them」，且只给「serious destructive consequences that cannot be easily undone」的动作。

### 五种状态（缺一不可）

默认 / 鼠标移上去 / 按下 / 键盘选中 / 不可用。**「看得出能点」靠的是这五个状态有区别，不是靠背景色更鲜艳。**

- 悬停与按下必须有可见变化（底色加深一档）。
- 键盘选中用 2px 强调色描边 + 2px 间距，鼠标点击不出现焦点环。
- 不可用：降低透明度 + 禁止光标，**并且旁边要有文字说明为什么不能点**；能在按钮文字里说清的（如「看效果（0）」），就不再另写提示。

### 尺寸与文字

- 高度：32（默认）/ 28（浮层工具条里）/ 40（触屏与主要提交）。参照 Ant 的 32/40/24 与 GOV.UK 的 44 触屏目标。
- **悬浮胶囊是例外（#109）**：它浮在别人的内容上，越小越好——整壳收到 WCAG 2.5.8 允许的最小：高 26（可点区 24 + 上下边框各 1）；0.8.6 单一形态、0.8.8 起无拖动把手（ADR-0016），四段全 24 图标钮，宽约 101；段内边距与外框内边距已压到 0，**不再有更大的版本**。触屏下四个图标钮放大到 40×40（无障碍优先于低调）。
- **胶囊闲置不透明度是对比度条款的例外（#110）**：插件设置页一根 10%–100% 滑杆（步长 10）调「闲置可见度」——悬停 / 键盘聚焦 / 拖动时回到 100%，那一刻满足对比度；闲置时不要求每档文字 ≥4.5:1，10% 约 1.2:1 是用户主动选择的可见度（iOS 辅助触控、OPPO 悬浮球同类）。低档（≤30%）设置页有一句提醒；`forced-colors` 下强制 100%；幕布上的「恢复」按钮固定 100%，不接这个设置。例外登记于 `tests/toggle-opacity.test.ts` 注释，不要把「每档 ≥4.5」的测试加回来。
- 内边距：左右 14，图标与文字间距 4。
- 圆角 8，与输入框一致（`--pm-radius-control`）；键帽等一行字高的小件用 `--pm-radius-small`（4px，#171 登记：8px 会把键帽撑成胶囊）。
- **键帽只有一份样式**（#171）：`styles/controls.css` 的 `.pm-kbd`（`--pm-border-control` 边 + `--pm-radius-small` + muted 色）。凡是「这个动作还有一条键盘通路」的提示都用它，不许各界面自写。
- 文字：动词 + 对象。「只改标题，完成」这种提前结束的路径，按 GOV.UK 的「Save and come back later」模式，必须说清它会保存并结束。

### 文字入口（#188）

散在界面里「一行字当入口」的样式，先回答两个问题再定样子：**点它去哪、做什么**（定档），**靠什么看得出能点**（定形态）。本节收编此前散在各票里的既有决定（#74、#99、0.8.12、0.8.16 发版审查），全项目的文字入口按这一张表归档：

**先分链接还是按钮**：去别的页面 = 链接（`<a>`）；对本页 / 本网站做动作 = 按钮。依据 Carbon · Link 的分工原话：「Do not use links for actions that will change data or manipulate how it is displayed, change a state, or trigger an action」。

| 档 | 是什么 | 颜色 | 「能点」的信号 |
|---|---|---|---|
| 导航链接 | `<a>`，离开当前页面（返回列表、去 Chrome 的页面、外站） | 蓝（accent） | 常驻下划线 |
| 次级入口链接 | `<a>`，本产品内的次要去向（弹窗底部两个入口、「查看使用说明」） | 灰（fg-muted） | 常驻下划线 |
| 文字按钮 | `<button>`，对本页做动作（「跳过引导」「到 Chrome 里设置快捷键」） | 灰（fg-muted） | 悬停出浅灰底 |
| 嵌流文字按钮 | `<button>`，与标题 / 说明文字同排、中间没有控件隔开的动作（「恢复…」出口、撤销、「全部删掉」） | 正文色（fg） | 常驻下划线 + 正文色，与旁边的 muted 文字拉开一档 |
| 危险入口 | 红字，链接与按钮都可能是 | 红（danger） | 常驻下划线；后果写在文字或旁边 |

依据与取舍：

- **下划线是链接的默认**（GOV.UK · Links：「Links are blue and underlined by default」；Carbon 的内嵌链接同样「styled with an underline」）。Carbon 允许「单独摆放」的链接只在悬停加下划线，但本产品的文字入口普遍与说明文字同灰（#74 的教训：扫一眼分不清哪半句能点），所以取 GOV.UK 更保守的立场：链接一律常驻下划线。
- **文字按钮归按钮档，不因长得像文字就按链接处理**（Ant · Button：「Text button: used for the most secondary action」；悬停出浅灰底 = Ant 的 `textHoverBg`）。它不带下划线：单独一行的文字按钮（「到 Chrome 里设置快捷键」）靠悬停出底表达能点，下划线反而把它读成链接。例外见下方登记的例外清单（#187 给「跳过引导」换了档，依据写在那里）。
- **嵌在文字流里的文字按钮补下划线、取正文色**：它与 12px muted 的说明同排，悬停表达不了「能点」（悬停是鼠标才有的状态，键盘与触屏都没有「悬停一看」）；正文色是 Ant 文字按钮的取色口径（`textTextColor` ≈ 正文色，不是 muted），加下划线，入口就从说明里拉开了一档（色阶 + 字阶 + 字重共三处不同）。0.8.16 给恢复出口补下划线的既有决定收编于此。
- **颜色只表达轻重与去向，不表达「能不能点」**：蓝 = 离开本页；灰 = 本产品内的次级入口；红 = 危险。没有「可点 = 蓝、不可点 = 灰」的编码。
- 红字入口不管链接还是按钮都必须带下划线，且后果用文字写清（GOV.UK warning button：「Do not only rely on the red colour of a warning button to communicate the serious nature of the action」）。

登记的例外（每个都能一句话判定）：

- **整行链接的列表行**（管理页站点行）：可点信号 = 悬停底色 + 行尾 ›，行内文字（域名、「N 项可能失效」）不逐个加下划线——GOV.UK 明确「上下文已经说明这是链接」的场合可以去掉下划线，举的正是导航的例子（header / side navigation）。
- **按钮链接**（`a.button`，页头互跳入口）：视觉档归按钮（§四 四档），不带下划线。
- **pm-mark 状态标**：圆点 + 文字是「这里有问题」的状态（§二 第 5 条），不是入口；唯一可点的失效条（弹窗摘要里那颗）按危险入口档处理。
- **欢迎页「跳过引导」**（#187 定稿）：`<button>`——「结束引导」是动作不是去向，Carbon「动作不用链接」，元素不挪进链接档；形态取**次级入口链接档**（灰 fg-muted + 常驻下划线）。理由：它静置在欢迎页标题与副标题两行说明文字旁边，文字按钮档的悬停信号只有指针看得见（嵌流档同款结论：悬停是鼠标才有的状态，键盘与触屏没有「悬停一看」），同灰无下划线读不出能点（#74 的教训；弹窗删除入口 #175 先例——按钮 + 常驻下划线治「长得不像入口」）。与设置页「到 Chrome 里设置快捷键」不共形不冲突：那个独占一行、悬停信号够用，仍走文字按钮档；本条按上下文分档。

## 五、排布

1. **一屏一个主操作**，永远在最右。
2. **次操作在主操作的左边**；**退路（上一步、退出设置）在最左或右上角**。
3. **操作栏里只放按钮**。任何说明文字都不许塞进操作栏——说明跟着它解释的东西走：字段的提示在字段下面，列表的提示在列表里，按钮为什么不能点在它挡住的那件事旁边。
4. **一个符号只有一个意思**。✕ 全产品只表示「把这一项从列表里去掉」；关闭整个面板一律用文字（「退出设置」）。图标不能既当关闭又当删除。
5. **按钮间距 8**；同一组不超过三个，超过就收进「更多」。
6. 浮层内的操作栏固定在底部，不随内容滚动。
7. **卡片内边距两档**（#171 登记，视觉不动）：弹窗这类压在别人页面上的紧凑卡 12px（0.8.16 #153 用户定稿），整页视图（管理页 / 插件设置 / 欢迎页）的整页卡 16px——前者省的是稀缺的浮层高度，后者没有这个约束，松一档呼吸感更好。新界面按「浮层卡 12 / 整页卡 16」取档，不出现第三种。
8. **同一屏里带框卡片与不带框的行共用一条内容基准线**（#180）：一行文字的起点与行尾控件的终点，必须与卡片内容区落在同一条竖线上。卡片靠自己的 `border + padding` 收到这条线；不带框的裸行用同一个共享 token 的 `margin-inline` 收到**同一个值**（`--pm-card-inset = --pm-space-3 + 1px`，唯一定义在 `styles/tokens.css`），不许各写一份 13px 补偿值，也不许用负 margin / `overflow: hidden` 补差。**分组分隔线是可以整卡宽的例外**：它是容器级元素，不是内容行。

### 内容基准线的依据与取舍（#180）

| 来源 | 取用的规则 |
|---|---|
| iOS 设置 / SwiftUI Form | "a Toggle aligns its switch to the trailing edge"；每一行行尾控件落在同一条 trailing padding 上 |
| Readest DESIGN.md | "The visible right edge of every row's value (toggle, chevron icon, input text) MUST land at the same X — the row's trailing padding." |
| [Material 1 · Lists: Controls](https://m1.material.io/components/lists-controls.html) | "States and primary actions are placed on the left side of a list tile"、"Secondary actions and info should be placed on the right side of the title"——行首 / 行尾各归其位，才谈得上对齐 |
| [Carbon · Toggle](https://carbondesignsystem.com/components/toggle/usage/) | 标签间距统一到 8px 以 "improve consistency across our label spacing"：同类间距只取一个值 |
| `modern-web-guidance` · `css-layout` | "Use gap ... instead of child margins"、"Use logical properties ... for layout dimensions and spacing"、"fix them at the source"、"Do NOT use overflow: hidden to mask layout issues"、推到行末用 `margin-inline-start: auto` |

**为什么这样取舍**：毛病是「同一屏里同类位置用了两套内缩量」——带框卡片是 13px（12 padding + 1 border），裸行是 0，于是三个开关差 13px、页脚文字与卡片内容差 13px。从源头统一的做法是把「内容相对边界内缩多少」收成一个 token，卡片与裸行各自用自己合适的属性（`padding` / `margin-inline`）达到同一个值；链接行改两端对齐、间距用父级 `gap`（`margin-inline` 也是逻辑属性），推到行末用 `justify-content: space-between`（`margin-inline-start: auto` 的等价手段）。这样零布局重构、不动卡片结构、也不碰既有 E2E 几何断言。

**没有引入 `subgrid`、没把整屏重构成 grid**：虽然 `modern-web-guidance` 的 `css-layout` 推荐用 subgrid 解决 ragged edge，但弹窗是 `flex column`、卡片内也是 `flex`，改成 grid / subgrid 会重构整屏、动到 0.8.16（#153）定稿的卡片结构与 E2E 几何断言，收益不抵风险；上面「从源头统一、用逻辑属性与 gap、推到行末」这几条用共享 token 即可达成。**分组分隔线**保持整卡宽是登记在案的例外：它划分的是容器分组、不是一行内容，跨整卡宽是成熟做法（格式塔共同区域）。

|---|---|---|---|

## 七、UX 准则（可检查的条款）

准则名称见 AGENTS.md「设计与体验准则」。这里只列**能对着界面逐条核对**的条款，以及本项目怎么落地。

| 准则 | 条款 | 本项目怎么落 |
|---|---|---|
| 状态可见（Nielsen 1） | 任何有后果的动作都要当场给反馈 | 保存失败、授权失败、导入结果都有就地提示；胶囊切换后按钮文字立刻变 |
| 贴近真实世界（Nielsen 2） | 用用户的话，不用内部概念 | 界面不出现「规则 / 生效范围 / 授权 / 清爽模式」，见 GLOSSARY |
| 用户可控（Nielsen 3） | 有明确的退出与撤销 | 向导随时可退出（有未保存内容时先确认）；删除规则 5 秒内可撤销；幕布一键恢复 |
| 一致（Nielsen 4） | 同一个东西，全项目一个叫法、一个样子 | 见 GLOSSARY 与 §四；一个动作只许有一个名字 |
| 名称角色值（WCAG 4.1.2） | 自定义角色要兑现它的整套契约 | 胶囊菜单刻意不是 `role="menu"`（不提供方向键导航），所以里面的勾选项用 `role="switch" + aria-checked` + 可见勾选标记，不用孤立的 `menuitemcheckbox`；三行开关在弹窗 / 设置页收成 `role="group"`（#116） |
| 防错（Nielsen 5） | 先防再谈报错 | 破坏性动作二次确认并列出后果；标题不许留空导致 Chrome 显示网址这类坑写在提示里 |
| 识别优于回忆（Nielsen 6） | 需要的信息就摆在眼前 | 收起项列在面板里可逐条改，不让用户记选择器；默认值直接显示在占位里 |
| 简洁（Nielsen 8） | 不相关的东西不占位置 | 操作栏只放动作；说明跟着对象走；同一句话不说两遍 |
| 错误可恢复（Nielsen 9） | 说清发生了什么、怎么办 | 错误文案带原因与下一步（「刷新后再试一次」「点它右边的 ✕ 不收起这一项」） |

| 别逼人记（Miller） | 一次只处理一小撮 | 向导分三步；列表与表单分组，折叠次要项 |
| 跟随惯例（Jakob） | 别人怎么做就怎么做，除非有硬理由 | 主按钮在右下、取消在左、✕ 只表示移除、点击外面关闭浮层 |
| 谁和谁一组（格式塔邻近 / 共同区域） | 相关的东西挨着，不相关的东西分开 | 说明文字不放进操作栏；同一张卡里的控件才用底色框在一起 |

## 八、落地要求

1. 控件样式只有一份（`styles/controls.css`），扩展页面与所有页内浮层共用；各界面自己的样式表不许再写按钮。
2. 只用 `--pm-*` 里的颜色、字号、间距、圆角，不写字面值。
3. 改完一屏，按 AGENTS.md「界面整屏审查」的五条过一遍再交。
4. **同用途开关只有一套外观**（#116）：弹窗与设置页用全局的 `input[type=checkbox][switch]`；胶囊菜单里的勾选项仍是同一个 `.pm-tg-item`，只多一列 12px 的勾选标记（固定占位，拨动时文字不位移），不许另画一种开关。勾选标记用 SVG，不用字形——各平台字形大小不一，项目此前已因此换掉过点阵字符；**两态都要看得见**：选中是勾，未选中是同一个槽位里的淡空框（`--pm-border-control`，≥3:1），否则和菜单里的普通动作项分不清（#127）。三处都收成 `role="group"`。可连着拨几个的开关组，点一下不关菜单。
5. **组级说明要跟逐行说明分开**（#127）：弹窗与站点设置页里讲整组开关的那句话，用一条细分隔线 + 上内边距与上面几行隔开，不能排得像是最后一行开关的注脚。

## 九、动效（0.8.15 起，先立口径再用）

项目长期零动效。0.8.15 给状态变化补过渡（#149 胶囊开/关、#150 面板收起/展开），口径按此执行，不要各自发挥：

1. **只表达状态，不做装饰**：过渡用于「开 ↔ 关」「可点 ↔ 不可点」这类状态切换，让它不突然跳变。不给入场、滚动、悬停加花活。
2. **只动颜色类属性**：`color` / `background-color` / `border-color` / `box-shadow` / `opacity`。不动 `width` / `height` / `top` / `left`（触发布局，低端机会掉帧），不做位移与缩放。
3. **时长 150ms、曲线 `cubic-bezier(0.2, 0, 0.38, 0.9)`**（Carbon productive standard = M3 `DurationShort3`）。上限 400ms（Doherty 阈值：超过就打断心流）；超过 300ms 必须有理由写进注释。
4. **`prefers-reduced-motion` 不置 0ms**：保留 120ms 的纯色淡变，去掉位移、缩放与长动画。依据 WCAG 2.2 SC 2.3.3 + C39，以及 Apple HIG「减弱动态」的处理——状态变化本身不该消失，只该变得安静。
5. **布局变化不做补间**：折叠/展开、显隐这类改变盒子尺寸的动作瞬时完成（0.8.15 #150：给面板做高度补间会动到既有直接子选择器与 E2E 几何断言，收益不抵风险）。要做也只在外层包一层专用容器，别改既有结构。
6. **不写 `linear`**：线性缓动在状态切换上显得机械；需要「没有缓动」时就不做过渡。
7. **选中态的悬停 / 按下用 M3 state layer 薄层**（0.8.16 #152）：半透明覆盖层（`--pm-state-hover` / `--pm-state-press`）以 `box-shadow: inset 0 0 0 9999px` 全覆盖画法叠在选中底上——不改布局盒尺寸、`background` 不被覆盖（选中底在悬停下保持可见）；`forced-colors` 下薄层随 box-shadow 一起失效，由系统 Highlight 底接管。

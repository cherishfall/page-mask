# 幕布恢复按钮：可见但低调

0.3.0 的共识是「幕布上不放任何文字、图标、logo」，恢复入口是一个默认低对比度、悬停才显形的极小按钮。真机用下来这条走不通：纯色幕布上没有任何形状时，用户根本找不到"怎么回来"——应急功能的第一要求是**回得来**，不是绝对空无一物。0.4.0 推翻这条：幕布上保留一颗**睁眼图标的小按钮**（#50）。

形态定为：

- 一颗睁开的眼睛图标（与胶囊上「遮住」的闭眼图标同形、去掉斜线那一笔——闭眼是遮住，睁眼是看得见、能回来，语义成对）。
- 与页面右下角的小胶囊**同一套材质**（同一套背景、边框、圆角、阴影 tokens），同一个尺寸体系——用户在遮住前刚看过胶囊，遮住后按钮长相延续，不用重新学习。
- 常态不透明度 **85%**、只显示图标；悬停或键盘聚焦升到 100% 并显出「恢复」两个字。「恢复」始终占位、只变透明度，文字出现时按钮不位移。
- 可拖动、记住位置：已添加的站点写回该站胶囊坐标（遮住前后按钮不跳位），一次性脚本写回一份全局位置。松手位移超过阈值算拖动（不恢复），否则算点击（恢复）。

为什么是 85% 而不是更低的"低调"值：白色幕布上 50% 的深色图标对比度只有约 2:1，达不到非文本对比 3:1 的可识别门槛，也是"用户找不到按钮"的直接原因。85% 加图标形状，常态就足够发现；文字留给悬停，兼顾"低调"与"可发现"。

两条代码路径（已添加站点的内容脚本、未添加站点的一次性注入脚本）共用**同一份按钮实现与同一套样式**，肉眼分辨不出是两条路径。

## Considered Options

- **维持「幕布上什么都不放」**：被真机使用否决。应急场景下用户处在"页面突然全白"的状态，没有任何可点的东西等于把恢复交给记忆和运气。
- **恢复按钮沿用旧形态（50% 透明度、悬停显形）但换图标**：不解决根本问题——对比度不达标的入口等于没有入口；85% 是实测能"余光扫到"的最低档。
- **幕布上放一个带文字的大按钮**：否决。应急遮蔽要的是"旁人注意不到这里有什么"，一个醒目的按钮本身就是视觉焦点，与目的相反。
- **保留整根胶囊（含清爽/原样开关）在幕布上**：否决。幕布是临时状态，不参与清爽/原样切换；多出来的按钮只会诱导误操作，也违背"幕布上东西越少越好"。

## Consequences

- `docs/design.md`「幕布」一节的「不放任何文字、图标、logo」改写为「不放文字、logo，保留一颗图标按钮」。
- 按钮归幕布宿主所有，两条注入路径只引一份实现；重复遮住不叠加按钮、不重复注册监听。
- 拖动坐标写回存储意味着幕布（不落库的原则不变）之外多了一个持久化的**位置**——落的库是"按钮在哪"，不是"幕布开着"，不违反 ADR-0007 的"幕布是临时状态"。
- 键盘聚焦能到达按钮并显出「恢复」，幕布不阻断无障碍使用。

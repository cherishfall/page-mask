# 规则级数据模型：一条规则 = 藏什么 + 怎么藏 + 在哪藏

每条隐藏规则独立持有三要素：藏什么（元素定位，保存**多个候选选择器**，由稳到险排序，任一命中即算找到）、怎么藏（收起方案：彻底移除/原地留白/遮罩覆盖三选一）、在哪藏（生效范围：整站/仅某类页面/排除某类页面）。批量点选一次创建多条规则；一条规则只藏一个东西。

隐藏通过**注入用户样式表（chrome.scripting.insertCSS，带 !important）**实现，而非直接修改元素的行内样式，也**不向页面插入 `<style>` 标签**（行内样式会被网站框架重渲染洗掉；插入的 style 标签会被严格 CSP 站点拦截；insertCSS 走浏览器用户样式表通道，两者都免疫）——这是对抗现代网站动态渲染的关键。选择器生成直接采用成熟库 css-selector-generator（其生成器天然输出"从最简到兜底"的候选序列，即多候选设计），并开启"忽略 CSS-in-JS 机器生成类名"选项（css-、sc-、emotion- 等乱码类名跨版本不稳定，得到/微信读书/即刻等 React 系站点大量使用）；候选排序原则：id/aria/data-* 属性 > 语义化类名 > 结构路径（nth-child 只做最后备胎）。多候选选择器对抗"网站改版后选择器失配"：主选择器失配时自动降级尝试次级，全部失配才判定失效并触发体检提醒。

## Considered Options

- **一条规则包含一组元素**：被否决。预览时每个元素本就可能用不同方案，组内仍需逐元素记录，纯增加嵌套复杂度。
- **以"页面档案"为中心建模**（每个页面类型一份配置）：被否决。同一元素需在每个页面类型间复制配置，改一处忘一处。
- **行内样式修改**：被否决。SPA 重渲染即被洗掉。
- **单一选择器**：被否决。网站任何一次改版都可能令规则静默失效，这是同类扩展的常见差评来源。

## Consequences

- 展示按"当前页面生效的规则"分组（页面视角），存储按"规则+范围"（不复制），两者并存。
- 两条规则范围重叠且作用于同一元素时，后创建的生效（确定性优先，v1 不做冲突检测 UI）。
- 失效体检只在伪装态下采集与展示——原样态下规则本就不应用，此时体检只会产生假警报。
- 标题/图标的持续压制采用业界成熟模式：内容脚本改写 + 监听页面 head 变化自动补刀（SPA 框架改回标题/图标时立即压回）；参考实现 Tabee（chrome-tab-modifier）。

# 界面与体验审查（0.4.2 现状）

对照 AGENTS.md「设计与体验准则」逐项核对的结论。**只记问题，不记已经对的地方。**按严重程度排序，改法写在每条后面。

审查范围：插件弹窗、管理页（列表 / 站点设置）、插件设置、首次引导、三步设置向导、页内编辑面板、悬浮胶囊、标签页标题小面板、删除确认框。

## 逐条

### 1. 一屏出现多个实心主按钮（高）

- **管理页 · 列表**：每个待授权站点行里都有一个实心「允许访问」，再加上顶部整卡里的「全部允许」。三个站点待授权 = 四个蓝色主按钮。GOV.UK 与 Ant Design 都写明：一页（一个区块）只能有一个主按钮，多了就没人知道该点哪个。
- **管理页 · 站点设置**：待授权时「允许访问」是实心主按钮，同一个页面里「在页面上编辑」也是实心主按钮（此时它被禁用）。两个主按钮，其中一个还是不可用的。
- **改法**：行内「允许访问」降为次按钮，只有顶部「全部允许」保留主按钮；站点设置页按「这一屏最想让你做的事」只留一个主按钮，其余降级。

### 2. 三个图标按钮的可点区域小于 24×24（高）

| 控件 | 现在 | 要求 |
|---|---|---|
| 胶囊拖动把手 `.pm-tg-grip` | 16px 宽 | ≥24 |
| 胶囊「遮住」`.pm-tg-cover` | 22px | ≥24 |
| 胶囊「⋯」`.pm-tg-more` | 22px | ≥24 |

WCAG 2.2 的 2.5.8 要求可点区域至少 24×24（AA）；Fitts 定律同理：目标越小越难命中。胶囊是压在其他网页上的浮动控件，用户本来就在移动鼠标，这三个最小的按钮正好是最容易点空的。

其余图标按钮（向导 28、编辑面板 28、小面板 24、号码牌 24）达标。

**改法**：可点区域一律 24×24 起（图标本身可保持 13–16），触屏媒体查询下 40×40。

### 3. 出现 10px 字号（中）

`toggle.css` 里 `.pm-tg-grip { font-size: 10px }`，低于 `styles/tokens.css` 自己定的下限（最小 12px，明确写了「不再使用 11px」）。**改法**：把手改成 SVG 图标，或提到 12px。

### 4. 同一个动作有多种叫法（中）

| 动作 | 现在出现过的叫法 |
|---|---|
| 关掉页内面板 | 「退出设置」（向导）、「关闭」（小面板）、「关闭编辑面板」（编辑器，读屏）、对话框里的「退出」 |
| 再加一些收起项 | 「＋ 收起更多内容」（弹窗、编辑面板）、「开始选要收起的内容」（编辑面板空状态）、「在页面上编辑」（站点设置） |
| 从清单里去掉一项 | 「全部删掉」（向导）、「删掉第 N 项」（向导读屏）、「删除」（站点设置）、「删除设置」（对话框） |

一个动作三个名字，用户会以为它们是三件事（Jakob：别人怎么做就怎么做；Nielsen 4：内部一致）。

**改法**：关面板统一「退出设置」/「关闭」两类；增加统一「收起更多内容」；移除统一「取消选择」（未保存）与「移除」（已保存）。

### 5. 同一个按钮在不同界面两种样子（中）

「上一步」在首次引导里是无框文字按钮，在三步向导里是有框按钮。同样的动作，长得不一样，用户会怀疑是不是两回事。**改法**：按 `docs/design-ui.md` §四 统一为次按钮。

### 6. 重要导航入口被画成最弱样式（中）

弹窗底部的「你添加的网站」「插件设置」是通往管理页和设置页的**唯一**入口，却用了最弱的无框文字样式。用户要记住它们在哪（Nielsen 6），还得瞄准（Fitts）。**改法**：升为次按钮，或做成带箭头的整行入口。

### 7. 禁用态没有说明为什么不能点（中）

- 弹窗：开关在 `busy` 时禁用，旁边没有任何说明。
- 站点设置：「在页面上编辑」在正在打开时禁用，没有说明。

其余禁用态已经符合规矩（向导「下一步」的原因写在列表里、按钮文字带计数；「选大一点」的原因写在同一组上方）。**改法**：短暂禁用尽量改成「文字变进行时」；确实要禁用的，旁边给一行状态。

### 8. 向导第 3 步单行控件过多（中）

每一行同时有：名称输入框、收起方式三选、只这一个 / 同类一起二选、一行解释、删除按钮。三行叠起来，一屏十几个决定点（Hick），还要逐行记住上一行怎么填的（Miller）。

**改法**：默认值已经够用（消失 / 同类一起），把「收起方式」和「收起几个」折进「调整这一项」里，行上只留「名称 + 一句话摘要 + 调整」。这是这一屏最大的一处改动，需要单独做。

### 9. 控件尺寸与间距大量硬编码（低）

24 / 28 / 32px 的控件高度、6 / 10px 的间距散落在五个界面的样式里，没有走 token。形状上看着差不多，实际每处都差一两像素，正是「单个都对、凑一起不齐」的来源。**改法**：控件尺寸与常用间距进 `styles/tokens.css`，各界面只引用。

### 10. 两种「异常标记」样式不统一（低）

「需要允许访问」用警告色描边徽标，「可能失效」用红色文字 + 圆点。两者都是「这里有问题」，长成了两个样子。**改法**：统一成一种结构，只按「需要你处理」和「已经坏了」区分颜色。

## 不在本次范围

- 视觉风格（配色倾向、圆角大小）属于 `docs/design-ui.md` 已定的基础规范，不在这份审查里重复讨论。
- 功能缺失（例如没有快捷键）属于产品设计文档「永不做」清单，不在此列。

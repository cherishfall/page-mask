# 图片和视频变灰独立于主开关

日期：2026-11-08 · 状态：已采纳 · 修订：[ADR-0013](./0013-media-grayscale-and-curtain-mute.md) 决定 4 中「媒体开关只在清爽态生效的既有模型不变」 · 相关：ADR-0013

## 背景

0.8.0 把媒体做成了胶囊上的常驻「媒体」钮（ADR-0013），但保留了「灰度只在清爽态生效」的旧模型。产品所有者实测后指出结构性问题：**原样态下按媒体钮没有任何可见反应**——设置被记录、页面纹丝不动。同类扩展把这类细分开关都收在弹窗面板里（uBlock Origin 的死开关、Dark Reader 的可调无效、AdGuard 的暂停换大按钮、Privacy Badger 的隐藏+说明，均经源码核实），面板里可接受的"无效态"放到常驻胶囊上就是缺陷：胶囊上每颗按钮按下去都必须看得见反应。

深层的依据是四个功能的依赖结构：标题和图标、收起内容是**配置型**功能（进向导配置、设定后不动），灰度是**状态型**功能（免配置、随看随切），遮住是**动作型**。配置型共享主开关是合理的（同一次"收拾网站"的产物、承担临时看真实页面 / 规则坏了一键恢复 / 每天一键生效三个职责）；状态型独立才是对的。产品所有者的使用场景补了最后一刀：PageMask 隐藏的是网页**正经部分**，需要反复切原样"把那些部分还给我用"——灰度若被主开关压着，每次恢复都要跟着抖。

## 决定

1. **主开关（按你的设置显示 / 原样）收窄为只管「收起的内容 + 标签页标题和图标」这组定制**；灰度完全独立——`mediaGray` 开着就在两种状态下都生效，原样态下照常变灰。
2. 正式样式合成（`buildDisguiseCss`）内部分开判据：规则 CSS 跟随两态，媒体块只看 `mediaGray`；首帧防闪在原样态同样压住灰度块。
3. 胶囊顺序调整：媒体钮排在遮住钮**之前**（两种形态）——媒体是高频状态开关、遮住是低频应急动作，应急离主按钮最远。
4. 媒体钮开启态图标改为**只填实框内内容（山 + 太阳）、外框保持描边**：整颗填实会糊成一个方块；弹窗开关行的小图标同步同一套状态表达。

## Considered Options

- **保持主开关统管、修死按钮**（原样态按媒体 = 自动切清爽态并开灰度）：否决——按一颗媒体钮连带套用整套收起规则和标题图标，副作用更大，与"独立"的产品判断背道而驰。
- **灰度移出胶囊、回菜单**：否决——产品所有者要的正是胶囊直达（使用场景：随看随切）。
- **切灰度时不按停正在播放的视频**：否决——源码核实微博网页版默认也自动播放、动图均为 video 元素（X 靠 `loop` 属性、社区扩展以此识别 GIF），循环与自动播放**不会重发 play 事件**，不按停就一直在动；"视频停了"的惊讶是一次性且一击可恢复（点视频放行），说明文案已披露。

## Consequences

- 「原样」语义收窄：原样态下页面可能仍是灰的。术语表已改（清爽态/原样态管"收起的内容 + 标签页标题图标"这组定制）；灰度说明文案删去「只在按设置时起作用」句，改讲独立。
- `buildDisguiseCss` 签名改为接收整个 `SiteProfile`（判据内聚）；后台 `disguiseCssFor` 不再按两态短路；内容脚本 `restoreAll` 对灰度做与清爽态相同的首帧防闪。
- 媒体-only 配置的站点上主按钮无可视效果（收起与标题图标都为空）——罕见边角（配置只能经向导或导入产生），接受；灰度-only 的站点形态已在 #135（0.8.7）收口：胶囊挂载判据只在页面加载时评估，会话内不因配置变空而拆胶囊（0.8.5 起「弹窗直接开灰度」让灰-only 站点成为常态，胶囊恰靠 mediaGray 挂出，中途关灰度曾把胶囊整根拆掉）。
- 媒体钮开启态图标的「内容填实」约定写进 `ui/icons/MediaIcon.vue` 与 toggle.css，弹窗同步。

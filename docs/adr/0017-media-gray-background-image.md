# 背景图纳入灰度：内容脚本扫描打标记

日期：2026-11-10 · 状态：已采纳 · **修订：[ADR-0013](./0013-media-grayscale-and-curtain-mute.md) 决定 1 的「不变灰边界」** · 相关：ADR-0002（规则模型与样式表注入）、ADR-0013（灰度与幕布静音）、issue#154

## 背景

ADR-0013 把灰度边界定为「背景图、iframe 内嵌播放器、canvas、内联 SVG 不变灰」，理由是纯 CSS 选不出「带背景图的元素」。0.8.15 真机反馈：灰度在多抓鱼上整体失败。真实浏览器复现（`tmp/probe-dz-bg.mjs`，不入库）：多抓鱼首页只有 2 张 `<img>`（二维码与备案图标），书封 / 店铺头像等 **18 个内容图元素全部走 CSS background-image**——对这类站点，「图片和视频变灰」等于没开。背景图内容图（书封、封面、海报）与 `img` 在用户眼里没有区别，边界不该按实现技术划。

## 决定

1. **背景图元素纳入灰度**：内容脚本在灰度开启期间扫描计算样式 `background-image` 带 `url(` 的元素（渐变等无 url 的不算），打 `data-pm-media-bg` 标记；CSS 扩一段 `[data-pm-media-bg]:not([data-pm-media-keep]) { filter: grayscale(1) !important }`。豁免口径与 img 完全一致：渲染尺寸 ≤32×32 的小图标、来源含 emoji 的（同一枚 `data-pm-media-keep`）、本扩展自家 UI（`isOwnUiNode`）。
2. **扫描策略**：观察器增量扫描从「只收 img/video」改为「子树全扫」（新增节点里的背景图元素一并进待办，rAF 分批消化）；已挂标记的元素在 class / style 变化时重判（换图 / 改尺寸）；首帧扫描遇 >600 元素的大页面改走待办队列，会话中段开灰度不卡主线程。开关关闭即清掉全部标记。
3. **连带灰度如实告知**：`filter` 作用于整个元素，容器里的文字会跟着变灰——封面容器通常没有子文字（多抓鱼实测如此），可接受；这条边界写进 GLOSSARY 与 design.md，不夸大。
4. **仍不变灰**：iframe 内嵌播放器、`<canvas>`、内联 SVG（后两者本就没有独立的「图」元素可挂滤镜）。

## Considered Options

- **维持「背景图不变灰」边界**：否决——多抓鱼这类背景图站点的灰度等于失效，用户直接报障；边界按实现技术划不按用户感知划，是本票的根因。
- **只扫 inline style 背景图**（`el.style.backgroundImage`）：否决——class / 样式表给出的背景图（多抓鱼实测即有此类）会漏；计算样式全查的成本由 rAF 分批 + 600 元素阈值兜住。
- **对背景图容器内文字做反灰**（给子元素再注一层 filter 还原）：否决——嵌套滤镜叠算不可控，复杂度与「看起来变灰」的产品定位不成比例。

## Consequences

- `core/media.ts`（选择器与属性常量）、`ui/media-controller.ts`（扫描 / 打标 / 清理）扩展；CSS 文本变化由既有 prev→next swap 通道承载，不需要新注入记录。
- 观察器在灰度开启期间的全量开销略升（每次样式读取多一类），换的是「背景图站点灰度可用」；未开启的页面零开销不变。
- 仅靠运行中改 class 换上背景图的元素可能漏标（初始扫描 + 新增子树 + 已标记元素重判覆盖不到「从无到有」的那一次），刷新后生效——登记进 design.md 已知边界。
- 权限与注入通道零变化（ADR-0013 的「不需要新权限」结论不动）。

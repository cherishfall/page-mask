# 胶囊去把手：整根可拖、阈值消歧、方向键挂本体

日期：2026-11-09 · 状态：已采纳 · 修订：ADR-0015 决定 1（五段）与决定 4（把手悬停显隐） · 相关：ADR-0015、issue#136

## 背景

0.8.6 真机体感反馈：把手悬停显隐没有让胶囊变小——闲置虽透明但**保留占位**，静止形态里那颗钮的位置一直空着，新眼睛目检的结论是「看着像缺了一块、左右失衡」。产品所有者的诉求是：拖动功能只在真正拖动时存在，胶囊是对原页面的侵入，在符合规范的前提下越小越好。

调研结论（2026-11-09，悬浮控件形态专题）：**没有任何成熟产品用独立把手**——iOS AssistiveTouch、Loom、Grammarly、沉浸式翻译、KISS Translator 全部直接拖球 / 钮本体；点击与拖动的冲突一律靠移动距离阈值消歧（Motion 官方 3px、jQuery UI `distance` 同范式）。ADR-0015 当时否决「按住胶囊任意处拖动」的理由是「每颗按钮都要背上误拖 vs 点击的判别负担」——阈值方案（按下不抢事件、移动跨过阈值才转入拖动）把这个负担解决了，否决的前提不再成立。

## 决定

1. **去把手段**：胶囊从五段变四段（主按钮 / 媒体 / 遮住 / ⋯ 菜单），宽约 126px → 约 101px；高度 26px 不变（WCAG 2.5.8 下限，design-ui.md #109 尺寸例外维持）。左圆头移交主按钮。
2. **整根胶囊表面都能拖**：按下只记起点、不抢事件；指针移动 ≥8px 才 `setPointerCapture` 转入拖动（阈值取 8px，比库默认 1~3px 更防手抖误拖）；不足阈值的按下 / 抬起是正常点击，按钮 click 照常触发。跨过阈值后指针捕获到本体，click 落在本体上，按钮不会被拖动误触（N1「拖动容器吃掉 pointerdown」教训的正面解法）。
3. **方向键移动挂到胶囊本体**：本体成为可聚焦的 `role="group"`（Tab 停靠位总数不变：本体 → 四颗钮），箭头键移动 15px 的既有无障碍能力不回退；按钮聚焦时的方向键不劫持。
4. **自由定位语义不变**（ADR-0015 决定 3 原样保留）：不引入贴边吸附、不恢复停靠模型；视口夹紧（`clampPos`）与 KISS Translator #1060（拖出视口）的教训防线维持。
5. **触屏**：本体与直属按钮 `touch-action: none`，按住拖动不被页面滚动打断（与幕布恢复按钮同一做法）。

## Considered Options

- **保留把手、只把它做小**：否决——占位问题依旧，「只在拖动时存在」无从谈起；成熟产品零先例。
- **长按进入拖动**（Android 主屏惯例）：否决——桌面 Web 无此惯例，按住 500ms 才能拖反而难用；移动端未来若支持再引入。
- **拖动仅从空隙发起**：否决——空隙只有 1px，物理上抓不住，「能拖」名存实亡。
- **贴边吸附 + 边缘半隐**（Loom / Grammarly 先例）：本票不做——ADR-0015 自由定位是产品所有者的明确选择，不悄悄翻案；静默降不透明度（#110）已承担「不显眼」。

## Consequences

- ADR-0015 的「E2E 锁 idle opacity=0 / hover opacity=1」随把手退场作废；新锁：无把手节点 + 本体拖动跟手落库 + 阈值内点击不误拖（按钮状态不变）。
- 宽度相关断言（118–134 → 96–106）与触屏命中区清单同步改写；`GripIcon` 在向导工具条的使用保留（#83 共享纪律不变）。
- 拖动的可发现性：空隙 / 边框上的抓手光标 + 本体 `role="group"` 的读屏名称（「按住拖动，或用方向键移动位置」）+ 菜单「按钮放回右下角」兜底；WCAG 2.5.7（拖动功能需有非拖动替代）由方向键路径与归位菜单项共同承担，键盘移动比调研发现的任何产品先例（查无）更进一步。
- 一次性首用引导（非模态提示「可拖动、贴边」）未做：等真机体感反馈再议，避免过度工程（NN/g：先用非侵入手段）。

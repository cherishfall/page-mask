# 幕布快捷键：唯一一条键盘入口

`docs/design.md` 的「永不做」清单第一行是「键盘快捷键（两次明确否决）」，理由是不想让扩展到处抢键。0.5.5 装机复核后，产品所有者提出：幕布是唯一「重要且紧急」的动作（有人走过来），那时鼠标往往来不及找，还是得有一条键盘通路。

这次推翻旧决定，但只开一个口子：**全产品只有幕布一条快捷键，其他任何功能一律不加**。当初担心的是「每个动作都配一个键」，而不是「存在一个键」；单条、只服务应急动作、不与任何设置项绑定的命令，不构成那种污染。

## 决定

- 一条命令 `toggle-curtain`：按一次遮住，再按一次恢复。
- 默认 `Ctrl+Shift+X`（Windows / Linux），`Command+Shift+X`（macOS）。避开 Chrome 保留组合（`Ctrl+Shift+T/N/W/B/O/I/J/C`）与 macOS 系统键（`⌘⇧H` 个人文件夹、`⌘⇧E` 推出）；X 取「收起 / 遮住」，左手单手可及。
- 不做 `global`（Chrome 未聚焦也响应）：ChromeOS 不支持全局命令，且 global 预设只允许 `Ctrl+Shift+0~9`；页面都看不见时按了也没意义。
- 改键只能在 `chrome://extensions/shortcuts`。扩展没有「自己设置快捷键」的 API，也不做页面内录制——那只在网页有焦点时有效，录不到浏览器级组合。
- 快捷键算一次用户手势，Chrome 会临时授予 `activeTab`：**没添加过的网站也能遮**，正好覆盖「正在看一个陌生网站」的场景。
- 遮不了 `chrome://`、Chrome 商店、PDF 阅读器、`file://`（扩展注入不进去）。失败不能静默：扩展图标给 3 秒的 `!` 角标 + 悬停说明。

## Considered Options

- **页面内 `keydown` 监听**：否决。会和网站自己的快捷键打架，而且没添加过的网站没有内容脚本，覆盖不全；也拿不到浏览器级组合（如 `Ctrl+Shift+Tab`）。
- **`global: true`**：否决。理由见上；应急场景里页面一定是可见的，Chrome 一定在前台。
- **允许单键（`Esc`、`~`）**：做不到。Chrome 要求扩展快捷键至少带一个修饰键，这是平台限制。
- **给其他动作也配快捷键**：明确否决。这会回到当初担心的「快捷键污染」，也让「只有幕布是应急动作」这个边界失守。

## Consequences

- `docs/design.md`「永不做」第一条改写为「除幕布外不加快捷键」；「幕布」「界面清单（插件设置页）」补上快捷键。
- 插件设置页新增「快捷键」区块：显示 `chrome.commands.getAll()` 的**当前实际绑定**（用户改过就显示改后的），未绑定时给警告（被别的扩展占用时 Chrome 会静默不绑定）。
- 弹窗「遮住这一页」按钮上带当前平台的键位提示；设置页写全两个平台（Windows / Mac 写法不同）。
- 不新增任何权限：`commands` 不需要权限声明。
- 浏览器级快捷键在自动化里触发不了（CDP 只能发页面级按键），命令分支靠 fake browser 单测覆盖，真机路径必须手测——交付时如实说明，不谎报。

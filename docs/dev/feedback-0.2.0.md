# 0.2.0 真机使用反馈台账

用户把 0.2.0 装进日常浏览器使用后提出的 8 条问题与新想法。本文记录每条的原话要点、代码调查结论、定稿方案与理由；实现细节在落地后补进 [DEVLOG.md](./DEVLOG.md)。

反馈批次进入 0.3.0。设计共识已同步回 [docs/design.md](../design.md)，术语已同步回 [GLOSSARY.md](../../GLOSSARY.md)。

约定：**「代码事实」= 可在仓库里指出行号的行为；「定稿」= 已经和用户对齐、可以直接实现的结论。**

---

## 1. 新站点授权后不进入向导，必须再点一次扩展图标

**用户原话**：点扩展 → 弹出网站授权 → 点「允许」→ 什么都不发生；得再点一次扩展才会进入引导配置界面。

**代码事实**：`entrypoints/popup/App.vue` 里 `permissions.request` 在 popup 上下文中被 `await`，而权限框弹出时 Chrome 会销毁 popup 文档，`await` 之后的 `enableSite` 消息从未发出。后台虽然监听了 `permissions.onAdded`，但 `core/reconcile.ts` 的注册计划只遍历「已有配置」的来源，新站点是空操作。第二次点击能进，是因为权限已存在、`request` 立即返回、popup 没被销毁。

这条早被标为「未验证风险」：`docs/dev/review/REVIEW.md` 第 169 行、`docs/dev/review/appendix-ui.md` 第 321 行。E2E 用替身替换了 `permissions.request`，从未真正跑过真实权限弹窗。

**定稿**：把「请求权限 → 对账 → 注入 → 开向导」整条链搬到后台。popup 只发一条消息；后台 `onMessage` 监听器里**第一句**就调 `permissions.request`（用户手势可跨 `runtime.sendMessage` 传到后台，但只在同一个同步回合内有效，之前不能有任何 `await`），`await` 之后继续跑完整个流程。popup 死不死都不影响结果。「重新授权」同一写法、同一个雷，一并改。

**不采用**：在 `storage.session` 里写「待开向导意图」由 `onAdded` 恢复。能work，但多一个状态、多一个过期清理、还多一个竞态，而现在的方案不需要任何持久状态。

## 2. 只想改标签页标题，向导却强制至少选一个元素

**代码事实**：0 条规则的站点在架构上已经是一等公民——`core/validate.ts` 只要求 `hideRules` 是数组，存储、注入、悬浮按钮、失效体检全部正常。唯一的堵点是 `ui/wizard/WizardApp.vue` 把「预览」按钮 `disabled` 在 `selEls.length === 0`，加上 `enterPreview` 里的早退。但向导里没有任何标题输入框，放开 0 条也只能存默认标题。

**定稿**：**不在向导里加逃生口**。向导的语义就是「进入全屏点选」，在里面找「我不选了」等于承认入口错了。改为在管理页的站点设置页完成：popup 对未配置站点提供两个动作——主按钮「为当前网站开启清爽模式」进向导；次按钮「设置标题和图标」深链到该站设置页，在那里授权、填标题、选图标、保存 0 条规则。

**理由**：站点设置页本来就要做（见第 6、7 条），标题/图标的编辑逻辑只需要存在一处；popup 只有 320px 宽，且**文件选择框同样会销毁 popup**，图标上传永远不能放进 popup。

## 3. 预览清单：收起方式藏在弹片里、措辞别扭、「只收起点选的这一个」读不懂

**代码事实**：

- 清单行是 `① 名称` + 一行**纯文本**（不是控件，没有 click、没有 tabindex）+「调整」按钮；三个收起方式和「移出本次选择」都在弹片里。
- 三个方式当前的界面叫法是「彻底移除 / 原地留白 / 遮罩覆盖」。
- 「只收起点选的这一个」是 checkbox，**默认不勾**，含义是「不勾 = 页面上同类元素一起收起」——用「不勾选」表达默认行为，还要求先理解「同类」。
- `onlyThis` 不进 CSS，只影响选择器是否做泛化，所以真正差别是**命中集合**，不是视觉声明。
- 名称退化到「div 元素」是因为 `core/naming.ts` 只收集元素的**直接**文本节点，容器元素的文字都在子节点里，于是落到 `${tag} 元素` 兜底。

**定稿**：

- 收起方式提到每一行：`① 名称 [消失][留空][盖住] ✕`。弹片整个删掉。
- **三选一改用原生 radio group**，不再用 `aria-pressed` 按钮：后者只告诉读屏「按下/未按下」，用户不知道这是三选一、也不知道还有别的选项；radio group 会报「3 选 1，当前第 2 项」，方向键直接切换。
- 名称行内可编辑（无边框，悬停/聚焦才显形）。
- 「同类」做成行内状态标签：`[仅这一处]` ↔ `[同类 3 处]`，数字实时计算，点一下切换。命中只有 1 处时显示「仅这一处」且不可点。
- 选中的方式下面显示一句白话解释（只显示当前那一条）：消失 = 下面的内容往上补；留空 = 位置留着不动；盖住 = 盖一块和背景同色的板。
- `✕` 默认中性灰、悬停变红，读屏文案「不收起这一项」。全界面不再出现「移除/移出」，与收起方式的措辞撞车问题消失。
- 预览里点号码牌 = 滚到对应行并高亮（原来点号码牌是打开弹片）。
- 元素命名：没有直接文本时改为取**后代**文本的前几个字，仍拿不到才用标签名兜底。

## 4. 点选到一半不想选了，没有出口

**代码事实**：工具条只有「选大一点 / 选小一点 / 预览（N）/ 退出」，没有清空已选；逐个取消只能再点一次已选元素。`退出` 与 Esc 走同一条路，只有存在未保存内容时才二次确认。

**定稿**：点选阶段工具条改为 `[选大一点][选小一点] …… [清空（N）][预览（N）][取消]`。「清空」只在 N>0 时出现，一点清光全部已选、**留在点选模式**。

---

## 5. 「退出」语义不明，危险按钮视觉反了

**代码事实**：确认框里「退出」是中性次按钮，「继续编辑」是 `primary` 蓝色主按钮且默认聚焦——危险/安全的视觉层级是反的。项目里「危险」有三套实现：管理页（红字 / 实底红）、编辑面板（红字 + 红边）、向导（只有红字、无边框）。

**定稿**：

- `退出` 统一改叫**取消**：`退出` 容易被读成「退出点选模式回到上一步」，而它实际是「放弃这次设置并关掉」。
- 确认框：标题「放弃这些设置？」；`[继续编辑]`（次按钮，默认聚焦）+ `[放弃]`（实底红）。
- 危险色收敛成两条全局规范：`.danger` = 红字红边（行内次级），`.primary.danger` = 实底红（确认框里的主危险）。三处实现统一。

## 6. 站点级配置（标题/图标/一键清空）应该收在站点自己的页面上

**代码事实**：管理页是一页到底的卡片流：全局默认标题 → 每个站点一张大卡（开关 / 标题 / 图标 / 一键清空）→ 导出导入。没有 tab、没有路由。图标压缩逻辑（`compressIcon`）锁在页面的 SFC 里，没有独立模块。管理页是独立扩展标签页，加 hash 路由零成本（扩展页天然可带 hash）。

**定稿**：站点级设置收进**站点设置页**，列表页只回答「我配了哪些网站、各自什么状态」。

- 详情：开关 → 标签页标题（输入 + 快捷填入）→ 标签页图标（预览 + 上传/清除）→ 已收起 N 项 → 可能失效提示 → 页脚「一键清空」。
- 规则列表在详情页可读、可删（5 秒撤销）；换收起方式、重选元素需要页面上下文，仍在页面内编辑面板做，详情页给「在页面上编辑」跳过去。

---

## 7. 管理页要拆成「网站」和「插件设置」两个页面

**定稿**：顶部两个 tab：**网站** / **设置**。网站 tab = 列表（图标、域名、清爽/原样、已收起 N 项、可能失效 N 项），点行进站点设置页；设置 tab = 全局默认标题、导出/导入、关于（版本、仓库地址、反馈入口）。

导航用 `<a>` + `aria-current`，**不用 ARIA `role="tab"`**：真实 tab 角色要求方向键切换面板，而这两个视图各有独立 URL、要支持浏览器前进后退和深链，用链接语义才对，读屏也不会被误导。

路由手写 `#/sites`、`#/sites/<域名>`、`#/settings`，不引路由库。

## 8. 一键遮住整页（幕布）

**用户原话**：事发突然，即便处于清爽模式，网页内容也不想被人看到；一点，整个网页连标题一起被遮住；人走之后再一点，恢复成点之前的样子——不管点之前是清爽态还是原样态。

**代码事实**：

- 内容脚本只注册给「有配置且已授权」的站点（`core/reconcile.ts`、`core/registration.ts`）。从未添加的网站没有脚本、没有页面内界面。
- 扩展图标绑的是 popup，不是 `action.onClicked`；键盘快捷键在设计文档的「永不做」清单里。
- 开关只有 `disguised` / `original` 两态，按站点持久化，没有临时态概念。
- 标题改写由 `TitleFaviconGuard` 负责，`restore()` 会还原成站点最近写入的真实标题——清爽态下不能调它，否则当场露馅。

**定稿**：

- 已添加的站点：纯页面内实现，**不进数据模型、不落库、不碰开关状态**，只影响当前标签页。
- 颜色取页面自己的画布底色（`html`/`body` 第一个不透明的 `background-color`），取不到才用白/深色兜底；固定白屏在深色页面上一眼就看得出不是这个页面。
- 幕布上不放任何常驻内容；恢复入口是悬浮按钮上的「恢复」（详见 design.md 的形态决定）。
- 标题/图标走和清爽态同一套（站点标题 > 全局默认 > 语言默认；透明图标）。
- 恢复按点击前的状态分支：清爽态还原成清爽标题，原样态还原成真实标题。
- 不跨刷新：刷新或整页跳转后即恢复；SPA 站内切换不受影响。
- 未添加的网站：走 popup 里一个「遮住本页」按钮，靠 `activeTab` 临时注入一份轻量脚本。**两次点击**，刷新即恢复。

**边界（已写进 design.md 已知边界）**：

1. 视频全屏、页面内 `<dialog>` / popover 在浏览器 top layer 之上，会盖住幕布。
2. 标签页悬停缩略图、浏览历史里的标题仍是真实标题。
3. 幕布只挡眼睛不挡输入——键盘焦点仍在页面里，继续打字仍会改内容。
4. 幕布不是安全边界：页面脚本可以直接删掉插件宿主。

## 跨条目的共性结论

- **popup 是会死的上下文**：权限框、文件选择框都会销毁它。凡是「点了之后还要继续干活」的流程，都不能写在 popup 的 `await` 之后。
- **只有一个编辑处**：站点级设置（标题、图标、清空）只在站点设置页；规则编辑（换方式、重选）只在页面内；向导只负责选元素。三处界面各自回答一个问题，不重叠。
- **互斥选项用原生控件**：三个收起方式用 radio，不用 `aria-pressed` 按钮；跨 URL 的导航用链接，不用 ARIA tab。

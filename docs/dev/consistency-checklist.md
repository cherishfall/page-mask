# 一致性复查清单

> 性质声明：本清单**只是索引，不是权威**。每条必须挂靠权威来源；与权威冲突时以权威为准。用户推翻某个判断时：同一提交里改权威文件、删本清单条目、全项目扫一遍旧样式 / 旧叫法。种子条目来自 2026-11-05 对六波反馈、十余轮返工记录的归类（证据指针见「首次发现」列）。

| # | 缺陷模式（大白话） | 判据 | 权威来源 | 首次发现 |
|---|---|---|---|---|
| 1 | 同一控件在两个界面长得不一样 | 按钮高度 / 圆角 / 字号 / 字重 / 图标 / 位置 / 顺序，两处对照不一致即算 | `docs/design-ui.md`「同一个东西全项目只有一个样子」；AGENTS.md 整屏审查第 5 条 | #65（一按钮抄五份）、#79、#80、#74 |
| 2 | 同一概念两处叫法不一样 | 中英文文案各查一遍；GLOSSARY 里没有的叫法出现即算 | `GLOSSARY.md`（唯一权威，含 _Avoid_ 禁用叫法） | #64、0.4.1 全界面重写、#71 |

## 使用方式

- 交接关 / 发版关的「新眼睛」审查员逐条对照本清单看截图。
- 日常自查：改完一处界面，按 AGENTS.md「界面整屏审查」五条 + 本清单 1~3 条（样式 / 叫法 / 文案）快速过一遍。
- 新条目入表：用户报了新问题时，先判它属于哪一类——已有条目则记入「首次发现」，没有则新增一行并补齐权威来源；**没有权威来源的条目不许入表**。
